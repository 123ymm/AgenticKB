# 02 · 核心概念词典

读懂平台页面和后续章节所需的全部词汇，每个词一段大白话。**按"组织 → 内容 → 加工 → 使用"的顺序排列。**

## 组织类

### 域（domain）

账号和知识库的外层边界：账号属于哪个域，检索就用哪个域；知识库归属其创建者的域。除站点管理员外，域是拥有者、库成员和公开可见性的共同外层边界。当前部署通常只有一个域（默认 `default`）。

### 三种角色

| 角色 | 能干什么 | 关键规则 |
|---|---|---|
| **站点管理员** | 全域通行；全局用户管理（建账号、重置密码、分配域权限） | 不写域绑定表；全域通行 |
| **域管理员** | 管理自己作为管理员的域 | 必须是密码账号；只能给本域添加普通成员，不能授予管理员、不能操作其他域 |
| **普通成员** | 使用被授权的知识库 | 库内能做什么由库内角色决定 |

### 库内角色（每个知识库内部）

| 角色 | 能做什么 |
|---|---|
| **拥有者（owner）** | 库的一切管理：成员、绑定范式、转移所有权、删除库 |
| **编辑者（editor）** | 上传/修改文件、发起挖掘、管理成员 |
| **只读（viewer）** | 浏览与检索 |

读权限判断："拥有者 / 库成员 / 库是 public，三选一即可读"。公开库全员可读，无需添加只读成员——成员入口仅用于授予**编辑者**写权限。

### 用户状态

| 状态 | 含义 |
|---|---|
| active | 正常使用 |
| disabled | 可恢复的暂停：保留域、库关系和 MCP 配置，但所有 Web/API/MCP 访问实时拒绝（管理员可恢复账号） |
| deleted | 永久清退：权限、成员关系和 MCP 全部清除；用户名保留不复用 |

### 知识库（knowledge base）

保存有权限的原始资料、来源、版本和加工视图的"仓库"。关键属性：

- **可见性**：`private`（仅拥有者和成员）/ `public`（本域全员可读）；
- **拥有者**：归属创建者所在域，可转移；
- **开放库标记**：在「MCP 接入」页勾选后，你的 Agent 钥匙才能检索该库（见 MCP 钥匙词条）。

## 内容类

### 文档（document）与版本

进入知识库的每一份资料。支持目录、归档包（zip/hdx/chm）、文档版本、替换、删除和恢复。删除走统一硬删管线，关联快照按生命周期回收（见快照词条）。

### 批次与挖掘 Run

上传的文件形成批次；对批次发起一次挖掘就是一个 **Run**。Run 按所选挖掘范式的冻结版本执行（见下）。**增量规则**：重新点挖掘会自动跳过已成功（或内容未变化）的文档、只挖失败和新增的——部分文件失败不影响已入库部分被检索。

### 快照（snapshot）

一次成功挖掘的产物集合。**知识产物只跟快照走**——快照被回收则产物全删。

**问：我删自己库的文件，会不会连累别的库？**
答：不会。快照按内容指纹在域级共享（同样内容跨库只存一份），删除时只有当一份快照**不再被任何库引用**（独占）时才会真正回收；还共享着的谁也删不掉。

被换下的快照进入废弃轨道：DEPRECATED 状态保留 7 天（期间切回范式不必重花 LLM 钱），到期独占才回收；重新挖掘相同内容会按指纹复活（DEPRECATED → 就绪）。检索读取的是"当前 serving 快照"。

### 检索就绪度

库详情页顶部的一眼可见状态，告诉你**这个库现在到底能搜什么**：

| 档位 | 含义 |
|---|---|
| 空库 | 还没有任何文档 |
| 已解析 | 文档进来了，还没切片 |
| 已切片 | 拆好了，还没建索引 |
| 关键词可搜 | 可以用关键词检索 |
| 语义可搜 | 语义（向量）检索可用——完整状态 |

若嵌入服务当时不可用，会显示"向量缺失已留痕"标记；恢复后重新挖掘可补齐语义检索。

### 发布（release）

域级的"已发布语料"范围——与知识库内容**互相独立**：知识库挖掘只构建、**永不进发布**。这解释了两个现象：设置页「知识资产」在纯知识库部署下恒显示"该域无发布语料"（口径不适用，不是数据丢了）；以及检索不传库范围时的行为（见第 14 章 kbIds）。

## 加工与查询类

### 挖掘范式 vs 检索范式（重要：两个不同的东西，UI 里都叫"范式"）

| | 挖掘范式（挖掘 Workflow） | 检索范式（paradigm） |
|---|---|---|
| 管什么 | **进料怎么加工**：一次挖掘 Run 跑哪些阶段（解析→切片→入库…） | **查询怎么找**：一次检索走什么算子链路（召回 → 过滤 → 组装） |
| 什么时候用 | 上传文件发起挖掘时选择 | 知识库自己绑定；未绑定用官方默认 |
| 页面 | `/mining/workflows` | `/paradigm` |
| 版本 | 发布后版本**不可变**（冻结 workflow + version + graph_hash + manifest），可按精确版本执行 | 拖拽编排算子 DAG，草稿/发布/归档三态，有版本号 |
| 共同点 | 全局共享、跨域通用，不随域切换 | 同左 |

不选择挖掘范式时，系统自动使用系统默认 Workflow。

## 使用类

### 检索三通道，一个引擎

系统只有**一个检索执行入口**，三种使用方式殊途同归、结果完全一致：

| 方式 | 适合谁 |
|---|---|
| 网页「知识库 → 检索」tab | 所有人，登录即用 |
| HTTP `POST /api/v1/paradigm/{paradigmId}/search` | 脚本、系统集成 |
| MCP 工具 `http://<服务器IP>:9000/mcp` + 个人密钥 | AI Agent |

检索前两个前提：① 目标库已完成一次成功挖掘（就绪度达到对应档位）；② 调用身份对该库有读取权限。

### 三种引用（ref）

检索/读取结果里返回的不透明引用，**原样回传**即可进一步取内容：

- `ev_…`：一条证据（检索命中的片段）
- `doc_…`：一篇文档（整篇分页读取）
- `st_…`：一个结构节点（章节/表格，可导航、可查表格）

统一响应协议：检索返回 `{query, evidence[], has_more}`，每条 evidence 带 `ref / type / content / source / truncated`——没有 score、rank、内部 id，网页和 MCP 拿到的是同一形状（HTTP 响应外层多一层 `evidenceResponse` 包装）。

### MCP 钥匙（kbm_…）

外部 Agent 接入平台的凭证，**用户级多钥匙**：一个用户可建多把（上限 10 把），**每个 Agent 一把、一把钥匙绑定一个知识域**，各钥匙的工具开关、开放库、提示词互不影响：

- `kbm_` 开头，**只显示一次**；
- 轮换后旧钥匙立即失效，每次调用都实时验钥；吊销后钥匙留在列表标「已吊销」，可再删除其展示记录；
- 只能检索你勾选为"开放"且你本人有权限的库（开放 ∩ 有权限）；
- 不传 `domain` 参数 = 钥匙绑定的域；传了必须等于钥匙域，否则报错；
- 无钥匙/错钥匙：工具清单返回空，一切调用被拒——Agent 什么也看不到，也不会泄露库是否存在。

### 一张网（知识一张网切片接入）

外部知识源以切片形式批量接入：切片不是旁路证据，也不单独建设一套检索——它进入现有解析和挖掘主链，**重建为可浏览、检索和引用的逻辑文档**；同一份资料完成一次加工后，可被多个业务知识库只读复用。来源的新增、修改、删除和权限变化通过重同步传播。
