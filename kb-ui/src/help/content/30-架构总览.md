# 30 · 架构总览：六服务一容器

面向开发者。讲清楚系统的运行形态、正式主链与不可破坏的架构约束。

## 运行形态

单容器 All-in-One，6 个服务由 supervisord 管理，nginx 是统一入口：

| 服务 | 容器内端口 | 宿主机映射 | 职责 | 技术 |
|---|---|---|---|---|
| nginx | 80 | **8080**（`CMKB_UI_PORT`，部署脚本禁止宿主机 80） | 前端静态文件 + 统一代理入口 | — |
| knowledge_mining | 8901 | 仅回环 127.0.0.1 | 知识挖掘（解析、入库、生命周期、KB 管理） | Python / FastAPI |
| llm_service | 8900 | 仅回环 | LLM 运行时（异步任务、模型调用审计） | Python / FastAPI |
| main_control_service | 8910 | 仅回环 | 主控配置中心（登录认证、JWT、域路由代理、品牌/重启） | Python |
| agent_serving_java | 8081 | 仅回环 | 检索与结构读取服务 | Java / Spring Boot |
| mcp_server | 9000 | **全网绑定**（外部 Agent 直连） | MCP 服务 | Python / FastMCP |

**对外只有两个口**：8080（人和脚本走 nginx）与 9000（Agent 直连 MCP）。其余服务全部只映射在部署机回环——外部一律走 8080 网关。

## 请求怎么进来（重要：单代理架构）

nginx 只有两个 location：`/`（前端 SPA 静态文件）和 `/api/control-plane/ → 127.0.0.1:8910`（转主控）。**所有后端 API 统一经 main_control_service 代理**——前端代码用 `proxyClient` 把请求发到 `/api/control-plane/api/v1/proxy/{domain}/{service}/...`，由主控按域路由转发到 mining/serving/llm。

```text
浏览器/脚本 ──8080──> nginx ──/api/control-plane/──> main_control:8910
                                                    ├─ proxy/{d}/mining/…  → 8901
                                                    ├─ proxy/{d}/serving/… → 8081
                                                    └─ proxy/{d}/llm/…     → 8900
外部 Agent ──9000──> mcp_server ──(内部)──> serving / mining
```

> README 中"`/api/mining`、`/api/serving`、`/api/llm`"的四前缀描述是历史形态，以本节与 `docker/nginx.conf` 为准。

## 正式主链（已核实，42 号文档）

```text
用户 / KB 权限
  → 逻辑目录与 Document 身份（PostgreSQL）
  → 当前原文件对象（MinIO；PostgreSQL 登记对象位置/hash）
  → KB 挖掘 Run 冻结对象与修订信息
  → 解析为 Parse IR，形成 Snapshot
  → 从 Snapshot 编译切片、结构、表格、检索表示与向量
  → Build 校验与有效文档选择
  → Java 检索、结构读取、网页和 MCP 消费
```

- 新上传默认走**对象存储**（MinIO），PostgreSQL 是业务事实源；`storage_path` 是迁移期 legacy 字段；
- 挖掘输入按**对象身份**读取（`jobs/run.py::_kb_object_documents`），不靠扫描上传目录。

## 必须保留的架构约束（42 号 §3）

| 约束 | 要求 |
|---|---|
| PostgreSQL 管业务事实，MinIO 管字节 | 目录改名/移动不搬字节；对象地址不承担用户文件树 |
| Document ID 是稳定身份 | 改名/移动不改知识身份、原对象与修订号 |
| Snapshot 是知识版本根 | 不新建独立的 ParseResult/SegmentSet 版本体系 |
| 文件当前态 ≠ 当前可搜索知识 | 用户明确知道在看哪种；证据回源固定对应来源 |
| 当前可搜索文档集合按同一合同解析 | 知识读取、统计、质量与搜索用同一有效集合 |
| 部分成功继续可用 | 一篇失败不使整库成功知识不可读 |
| 权限与服务可用性分别判断 | 无权可隐藏存在性；数据库故障不能伪装成无权 |

**启动依赖**：`main_control_service` 必须最先启动——它是配置唯一来源，mining/serving/llm 从它拉配置。**服务不从 `.env` 读应用配置**（`.env` 应用配置已废弃）；但注意内网服务器根目录的 `.env` 是首次部署自动生成的**内部密钥文件**（存 serving/mcp 内部鉴权密钥，600 权限），**不要删**（见第 40 章）。

## 配置体系

- 系统配置在 `main_control_service/config/system/*.yaml`（database / llm_service / auth / ui 等）+ `domain_registry.yaml`（域路由）；
- 内网配置**永不被部署/同步覆盖**（部署脚本强制不变式，见第 40 章）；
- `auth.yaml` 含 `jwt_secret` / `internal_verify_secret` / `bootstrap.admin_password`，缺文件即鉴权 fail-closed。
