# 17 · 挖掘范式（挖掘 Workflow）

页面：`/mining/workflows`（列表）、`/mining/workflows/:id`（编排器）｜仅站点管理员

## 这是什么

挖掘范式决定**一次挖掘 Run 跑哪些阶段**（解析→抽取→入库…）——"进料怎么加工"。与检索范式（第 18 章）是两个不同的东西。

核心特性：

- **全局共享**，不随域切换；
- 草稿使用 revision **乐观锁**；
- **已发布版本不可变**：发布即冻结 `workflow_id + workflow_version + graph_hash + manifest`，之后按批次选择**精确版本**执行；
- 上传文件挖掘时不选会用**系统默认** Workflow；
- 旧请求不传 Workflow 自动使用系统 FULL Pipeline。

## 列表页

| 列 | 说明 |
|---|---|
| 名称 | 带「系统默认」/「系统」标签 |
| 描述 | — |
| 草稿 | `r<revision>` 当前草稿乐观锁版本 |
| 当前版本 | `v<n>` 或"未发布" |
| 状态 | 已发布 / 已归档 |

操作：**编排/版本**（进编辑器）、**复制**、**归档**。新建弹窗标题为「新建挖掘范式」（名称+描述）。

## 编排器（画布）

- **左侧算子面板 → 双击或拖拽到画布**；节点带"当前必需 / 可选 / 禁用"标记，固定骨架节点不可删；
- **连线**：从节点拖到下游建立执行顺序；
- **保存草稿**：存在 revision 冲突时提示"放弃本地并加载远端"或"返回当前草稿"；离开页面有未保存改动会确认；
- **发布新版本**：先过**服务端校验**（未通过不能发布）；版本未改变时要求显式重新发布；
- **版本历史**：可查看/恢复历史版本——**历史版本只读**，恢复会生成新的草稿 revision（不覆盖当前发布版）；
- 调试辅助：复制本地 JSON。

## 与挖掘的关系（速查）

| 场景 | 行为 |
|---|---|
| 绑定范式 | 库详情「挖掘」tab 顶部选择（仅拥有者/编辑者可改） |
| 版本冻结 | 每次挖掘 Run 记录所用的精确版本，重放可追溯 |
| 范式变更 | 换范式/版本/图变了，挖掘时**自动强制重挖** |
| 已发布 manifest | 编译期冻结算子参数——改算子默认值对已发布版本无效，需重新发布工作流或靠域包策略覆盖 |
| 应急回退 | 显式配置 `MINING_RUN_SUBMISSION_ENGINE=legacy`（完整回退与回滚步骤见 `docs/mining-workflow-rollout-runbook.md`） |
