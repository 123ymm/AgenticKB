# 13 · 挖掘与审核

页面：库详情 ·「挖掘」tab、`/kb/:kbId/run/:runId`（运行详情）、库详情 ·「质量」tab｜发起需要拥有者或编辑者

## 挖掘是什么

把库里的文件加工成可检索知识的过程：解析 → 切片 → 表格抽取 → 索引/向量。一次挖掘 = 一个 **Run**（见第 02 章）。

## 「挖掘」tab：发起与记录

面板顶部是**挖掘范式选择**（显示当前版本），下方是**挖掘记录列表**（行可点进任务详情：实时进度 + 逐文档阶段流水线）。

**绑定范式是前置条件**：尚未选择挖掘范式时，页面明确提示"请先绑定一个已发布范式"——绑定入口就在本 tab 顶部。仅拥有者或编辑者可修改绑定。

### 发起方式（两种）

| 方式 | 入口 | 范围 |
|---|---|---|
| 整库挖掘 | 「挖掘」tab | 本库全部文档 |
| 挖掘选中 | 「文件」tab 多选 | 只挖选中的（挖掘触发统一在文件列表批量栏） |

两个可选项：

- **强制重挖**：忽略内容哈希缓存，对文档重跑完整 pipeline（含 LLM 阶段），重生已挖知识；
- **强制整库重挖**：对整库所有文档强制重跑。

**增量规则（不勾强制时）**：重新挖掘自动跳过已成功（或内容未变化）的文档、只挖失败和新增的——部分文件失败不影响已入库部分被检索。

**范式变更自动强制**：绑定的工作流版本/图变了，挖掘时自动强制重挖，无需人工勾选。

## 运行详情页：看懂一次挖掘

### 七种 Run 状态

排队中 / 运行中 / 已完成 / 已中断 / 失败 / 已取消 / 待人审。

### 阶段流水线（按真实事件动态渲染）

阶段条**不再预渲染固定骨架**——按本次 Run 真实记录的阶段事件动态显示，跑过哪些阶段显示哪些。阶段目录（`PipelineFlow.vue` STAGE_CATALOG）：

| 阶段 | 说明 |
|---|---|
| 解析 → 分段 | 文件解析与切片 |
| 段落理解 / 语篇分析 / 检索单元 | 篇章线加工 |
| 向量化 → 数据写入 | 语义索引 |
| 构建&发布 | 快照构建校验与入库（全局尾段） |

实体抽取/实体归一/关系抽取/落图等**本体线阶段仅历史 Run 出现**（旧任务会标注"历史任务"），当前挖掘链不产生这些阶段。页面轮询直到终态，**离开页面自动停止轮询**。

### 部分成功（最常见的"没跑完"形态）

横幅「任务部分完成」——绿底（有产出）带警示边（有失败）：**成功入库 N / 失败待重试 M / 跳过未变化 K**。

**失败的文档下次点击「挖掘」会自动重试，不影响已入库内容**——不需要挑出失败文档，直接再点一次挖掘即可（增量规则自动只挖失败的）。

### 人工审核（待人审）

工作流可以包含审核环节。Run 停在 `awaiting_review` 时：

- 横幅「挖掘已暂停，等待人工处理」显示暂停节点，带**「继续挖掘」**按钮——处理完成后点它恢复流水线；
- 概览页「待处理」区块会列出该库（见第 10 章）。

### 错误摘要

失败文档在详情页有**错误**列与错误摘要，逐文档可见失败原因。

## 「质量」tab：质量报告

挖掘完成后看库的质量面：**结构完整度、表格完整度、来源定位覆盖**，以及**不可精确查询表格的原因清单**——表格搜到了但不能精确查（缺表头/合并单元格等原因）会在这里解释。

## 挖掘完成后

- 看**检索就绪度**（库详情页顶部）确认能搜到什么档位（见第 02 章）；
- 想验证：切到「检索」tab 搜一条（见第 14 章）。

## 运维须知（开发者/管理员）

改了挖掘算子/范式/域包检索策略后，**已挖文档不会自动重生**（内容哈希去重 → SKIP 复用旧快照）。要应用新逻辑：重启 mining → 强制重挖（勾选或整库）。范式签名变更（版本/图变化）会自动强制，无需人工勾。
