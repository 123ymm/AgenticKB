# 21 · 常见问题与错误码

按"现象 → 原因 → 处置"组织。检索错误码完整表见第 14 章，本章收各处散落的坑。

## 账号与登录类

| 现象 | 原因 | 处置 |
|---|---|---|
| 忘记密码 | — | 找**站点管理员**在「用户管理」重置（域管理员不能改密码，第 20 章） |
| 一个库都看不到 | 没人给你授权 | 找库拥有者加成员 / 用公开库 / 自建（第 11/20 章） |
| 登录后管理菜单很少 | 导航按角色过滤（member 只见 概览/知识库/MCP 接入） | 正常；需要权限找站点管理员 |
| 平台地址打不开 | 端口/网络 | 内网部署默认 `http://<服务器IP>:8080`（以部署告知为准） |

## 检索类

| 现象 | 原因 | 处置 |
|---|---|---|
| 不传 kbIds 结果比预期多 | 不传 = **检索你在域内可见的全部库**（范围放大） | 显式传 kbIds 精确控制范围（第 14 章） |
| 400 `kb_ids_required` | 调用身份在域内一个可见库都没有 | 检查账号权限/域 |
| 检索 404 `kb_not_found` 但网页就绪度显示"语义可搜" | 99% 是权限问题（私有库且你不是拥有者/成员），不是数据问题 | 让拥有者加你为成员 / 设 public / 用拥有者身份（第 20 章） |
| 404 `no_active_kb_build` | 库还没挖完，或全部文档挖掘失败 | 先完成一次成功挖掘（第 13 章） |
| 网关路径 404 | `serving` 前缀拼漏 | 路径必须是 `/api/control-plane/api/v1/proxy/{domain}/serving/...` |
| 其他机器直连 8081 不通 | 检索服务只映射在部署机回环 | 其他机器走 8080 端口网关；`X-KB-User` 直连方式仅限部署机内部集成使用 |
| Windows curl 中文乱码/GBK 报错 | 命令行编码 | 请求体写成 UTF-8 的 json 文件，用 `--data-binary @body.json`，不要 `-d '中文'` 内联 |
| 脚本跑着跑着 401 | token 12 小时过期 | 捕获 401 自动重登 |
| 语义搜不准，用词不同就搜不到 | 就绪度只到「关键词可搜」 | 检查嵌入服务是否可用（"向量缺失已留痕"标记），恢复后重新挖掘补齐 |

## MCP 类

| 现象 | 原因 | 处置 |
|---|---|---|
| 连不上 `http://<IP>:9000/mcp`（连接超时） | 网络不通 | 查 Agent 所在机器到服务器 9000 端口的防火墙/安全组放行 |
| 能连通但 Agent 什么工具都看不到 | 无密钥/错密钥（tools/list 返回空） | 重新生成密钥并更新客户端配置 |
| 客户端没法配请求头 | 平台只认 `Authorization: Bearer` 头 | 换支持自定义请求头的客户端（第 15 章前提） |
| 轮换后 Agent 全部 401 | 轮换即旧钥失效（无宽限期，实时验钥） | 重新生成并更新所有使用方 |
| 报"工具未开放"/"知识库未开放" | 工具开关没开 / 开放库没勾 | 到「MCP 接入」页检查开关与勾选 |
| 创建钥匙被拒"已达上限" | 一个用户最多 10 把 | 吊销不需要的钥匙再建 |
| 报 `paradigm_domain_mismatch` | 显式传了别的域的范式 | 不传范式（自动跟随库绑定）或按提示改 |
| 报"该 MCP 钥匙绑定知识域 X，不支持指定其他域" | 钥匙是单域的 | 不传 domain（默认钥匙域）；要访问其他域就新建对应域的钥匙 |
| 表格查询报字段错 | DSL 不是模糊搜索，字段名必须来自能力报告 | 先 `get_knowledge(ref="st_…")` 看 `assets[].columns[].name` 再查 |

## 挖掘类

| 现象 | 原因 | 处置 |
|---|---|---|
| 挖掘报部分成功 | 部分文档失败，成功部分已入库 | 看错误摘要修问题；**下次点「挖掘」会自动重试失败文档**，不影响已入库内容 |
| 整条流水线卡住不动 | Run 停在待人审（`awaiting_review`） | 概览「待处理」点进 run 详情，处理后点横幅上的「继续挖掘」 |
| 改了算子/范式后旧文档内容没变 | 已挖文档不自动重生（内容哈希去重 → SKIP 复用旧快照） | 重启 mining 后**强制重挖**（选中或整库）；范式版本/图变化会自动强制 |
| 检索单元 table_row 爆量 | 已发布工作流 manifest 编译期冻结算子参数，改算子默认值无效 | 靠域包策略覆盖或重新发布工作流 |
| 挖掘刚上传的文件搜不到 | 上传自动排队挖掘，完成后才可检索 | 等挖掘完成；正在挖掘的库会排队串行执行 |

## 概览数字类

| 现象 | 原因 | 处置 |
|---|---|---|
| 概览有检索单元，系统状态「知识资产」是 0 | 两个口径：前者是库的当前知识，后者只统计域级发布语料（纯知识库部署恒为空，见第 02 章「发布」） | 正常，无需处理 |
| 检索次数掉到 0 | 多为接入断了（密钥轮换/网络），不是没人用 | 检查 Agent 连接与密钥 |
| 零结果率高 | 知识覆盖缺口 | 看「答不上来的问题」清单，补文档重新挖掘 |
| 普通成员看不到运维数据 | 设计如此（含真实用户输入，仅管理员可见） | 找管理员看 |

## 上传类

| 现象 | 原因 | 处置 |
|---|---|---|
| 大 zip 上传后文件列表暂时没有 | 归档在后台解压入库（最长约 30 分钟） | 稍后刷新文件列表 |
| 文件类型不支持 | 支持范围外 | 支持 Markdown/文本/HTML/PDF/Word 等；zip/hdx/chm 归档会自动解压 |
| 上传按钮不可用 | 权限不足（需拥有者或编辑者） | 找库拥有者加权限 |
