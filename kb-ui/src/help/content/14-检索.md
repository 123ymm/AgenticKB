# 14 · 检索

页面：库详情 ·「检索」tab｜所有人（对库有读权限即可）

系统只有**一个检索执行入口**，三种使用方式殊途同归：网页「检索」tab、HTTP POST、MCP 工具——背后是同一个引擎、同一个入口，结果完全一致。本章覆盖网页与 HTTP；MCP 见第 15 章。

## 前提（两个）

1. **目标库已完成一次成功的挖掘**（库详情页顶部「检索就绪度」达到「关键词可搜」或「语义可搜」）。部分文件失败不影响——成功入库的部分可检索；重新挖掘会自动跳过已成功、只重挖失败的。
2. **调用身份对该库有读取权限**：拥有者 / 库成员 / 库是 public，三选一。

## 网页检索（「检索」tab）

1. （可选）范式下拉保持**「跟随官方默认」**即可——调用方一般不用关心范式；
2. 输入问题（占位提示："输入问题，用当前管线测试这个知识库的检索…"）；
3. 点「检索」；每条结果是一张**证据卡片**：
   - **「查看完整」**：片段被截断（`truncated: true`）时展开完整证据；
   - **来源文件名 / 来源章节**：跳转文档预览与章节；
   - **「查看表格」**：命中表格时直接查结构化表格。
4. 从文档页发起的「本节搜索」会带范围参数跳转进来（范围锁定时显示"改回整篇"按钮，点「搜索整个知识库」解除）。

## HTTP 调用（脚本 / 系统集成）

### 第一步：登录拿 token

```bash
curl -s -X POST http://<服务器IP>:8080/api/control-plane/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username": "zhangsan", "password": "******"}'
# → {"token": "eyJhbci...", "user": {...}}    # 默认 12 小时有效
```

### 第二步：查我的库拿 kbId

```bash
curl -s "http://<服务器IP>:8080/api/control-plane/api/v1/proxy/default/mining/api/kb?domain=default" \
  -H "Authorization: Bearer $TOKEN"
# → [{id: "kb-xxxx", name: "...", visibility: "private", my_role: "owner", document_count: 123}, ...]
```

### 第三步：解析范式（拿 paradigmId）

```bash
curl -s "http://<服务器IP>:8080/api/control-plane/api/v1/proxy/default/serving/api/v1/paradigm/resolve?domain=default&kbIds=kb-xxxx" \
  -H "Authorization: Bearer $TOKEN"
# → {"bound": true, "paradigmId": "pd-ab12cd34", "name": "官方默认·混合检索", "version": 3,
#    "url": "/api/v1/paradigm/pd-ab12cd34/search", "source": "library|official"}
```

- `source` 两值：`library`=该库自己绑定的范式；`official`=回落到官方默认；
- `bound: false` = 库级绑定与官方默认**都不可用**——到「检索范式」页确认有已发布范式（第 18 章）；
- 全部可用范式：`GET .../serving/api/v1/paradigm/published`。

### 第四步：执行检索

```bash
curl -s -X POST "http://<服务器IP>:8080/api/control-plane/api/v1/proxy/default/serving/api/v1/paradigm/pd-ab12cd34/search" \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"query": "核心交换机的冗余电源配置要求", "domain": "default", "kbIds": ["kb-xxxx"], "top_k": 10}'
```

**请求体参数全表**：

| 字段 | 必填 | 说明 |
|---|---|---|
| `query` | ✅ | 检索词/自然语言问题；空串 → 400 `query_required` |
| `domain` | 建议 | 知识域，缺省 `default` |
| `kbIds` | **强烈建议** | 检索范围。**注意：不传 ≠ 没结果——不传表示"检索调用者在域内可见的全部知识库"（范围放大）**。想精确控制范围就显式传库清单；一个可见库都没有时报 400 `kb_ids_required`。可传多个库 |
| `top_k` | 可选 | 结果上限 1–200 |
| `within` | 可选 | 范围硬过滤，白名单五键：`document_refs` / `section_refs` / `section_scope`（`exact|descendants`，本节或本节及子节）/ `asset_types` / `evidence_types`（后两值即返回的 `evidence[].type`，可原样回传筛选） |
| `filters` | 可选 | 类型硬过滤，白名单同上（`within` 与 `filters` 走同一合并白名单，键可互换） |
| `expansion` | 可选 | `{"mode": "auto|exact|window|parent|whole_document"}`，证据粒度，默认 auto |
| `debug` | 可选 | true 时附 `trace`（算子执行留痕） |

**成功响应**（HTTP 外层多一层 `evidenceResponse` 包装，内层即统一协议）：

```json
{
  "evidenceResponse": {
    "query": "……",
    "evidence": [{
      "ref": "ev_8Jq3…",
      "type": "prose",
      "content": "核心交换机应配置双电源模块，N+1 冗余……",
      "source": {
        "knowledge_base": "网络设备手册", "file_name": "核心交换机运维手册.pdf",
        "document_ref": "doc_Kx2m…", "section": "3.2 电源配置", "page": 45
      },
      "truncated": false,
      "structure_ref": "st_9Pzq…"
    }],
    "has_more": false
  }
}
```

`type` 取值：`prose | section | table | table_row | list | code | formula | figure_caption | document`。

### 第五步（可选）：截断证据取全文

```bash
curl -s "http://<服务器IP>:8080/api/control-plane/api/v1/proxy/default/serving/api/v1/evidence/ev_8Jq3…?domain=default&kbId=kb-xxxx&mode=parent" \
  -H "Authorization: Bearer $TOKEN"
```

`mode`：`auto`（默认）/ `exact`（原片段）/ `window`（相邻切片）/ `parent`（父章节）/ `whole_document`（整篇）。

## 错误码对照

所有错误都是结构化响应 `{"error": "<code>", "message": "…"}`，不要猜 HTTP 状态码：

| HTTP | error code | 含义 | 怎么办 |
|---|---|---|---|
| 400 | `query_required` | 没传检索词 | 补 `query` |
| 400 | `kb_ids_required` | 调用者在域内**一个可见库都没有** | 检查账号权限/域 |
| 400 | `top_k_invalid` / `expansion_invalid` / `unsupported_scope_filter` | 参数越界/白名单外键 | 按取值范围改（过滤键白名单见上表） |
| 400 | `empty_scope` | 范围内没有可读内容 | 检查 kbIds / within 范围 |
| 401 | `unauthenticated` | 没带 / token 过期 | 重新登录 |
| 404 | `kb_not_found` | **库不存在或你对它没权限**（同码防探测） | 确认 kbId 与权限（第 20 章） |
| 404 | `no_active_kb_build` | 目标库没有可检索内容 | 先完成一次挖掘 |
| 500 | `internal_error` | 服务端异常 | 看检索服务日志 |

## 留痕

每次检索（网页/HTTP/MCP 同等）在 `serving_query_logs` 留一条：query 原文、域、耗时、范式、结果条数与来源。**不记录发起人**——三种方式在日志里无法区分谁发的。
