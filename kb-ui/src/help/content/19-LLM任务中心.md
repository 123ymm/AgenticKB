# 19 · LLM 任务中心

页面：`/llm`（概览）、`/llm/:taskId`（任务详情）｜仅站点管理员

## 这是什么

挖掘背后的 LLM 调用（embedding / generation / caption 等）走**异步任务**通道，这里是这些任务的观测台与清理台。历史任务会持续累积，可定期清理。

## 概览页

- **顶部数字**：成功率、排队中、卡死/失败、耗时、队列等当前域（知识域）的整体状况；
- **模型调用审计**：按调用方 / 类型 / 模板 / 阶段 / 模型维度看调用记录（创建时间、状态、解析结果、默认参数）；
- **模板**：提示词模板详情——模板与知识库业务数据相互独立，清理任务不影响模板；
- **任务详情**：点行进入 `/llm/:taskId`，看单任务阶段、进度与结果。

## 清理历史任务

LLM 任务表会随使用持续增长，页面提供**保留期清理**：

| 规则 | 说明 |
|---|---|
| 只删已结束 | 仅删除已结束（**成功 / 失败 / 死信 / 已取消**）且超过保留期的任务及其附属数据 |
| 不碰在跑的 | 排队中、运行中的任务不会被删除 |
| 预览先行 | 显示"将删除行数"再执行 |
| 可续清 | 一次没清完（如几十万行分批）提示"继续清理"，累计进度可见 |

> 大表清理是分批进行的——"本次清理未全部完成（N 个任务）未清理，可点击「继续清理」"是正常形态。

## 和挖掘的关系

- 挖掘的 LLM 阶段提交为异步任务（默认 async 模式）；
- 任务失败 → 挖掘侧对应文档失败，在挖掘 Run 详情能看到错误摘要（下次点「挖掘」会自动重试失败文档，第 13 章）；
- 卡死/失败任务长期堆积时，先看模型调用审计定位是哪类调用、哪个模板的问题。
