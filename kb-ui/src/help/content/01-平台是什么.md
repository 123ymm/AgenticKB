# 01 · 平台是什么

## 一句话

AgenticKB（产业知识底座）把分散在文档、系统和专家经验中的知识，**持续加工成有来源、可维护、能直接支持业务任务的知识资产**——它不是又一个"能搜索的知识库"。

## 用"仓库 + 工厂"理解它

| 组成 | 大白话职责 |
|---|---|
| 知识一张网 / 用户资料 | 进入工厂的**原材料** |
| 知识库 | 保存原料、来源、版本和权限的**仓库** |
| 挖掘流水线 | 给原料建目录、拆结构、提表格、建索引，让资料**可找、可读、可定位** |
| 检索范式 / 挖掘范式 | 两条流水线各自的**工艺卡**：查询怎么找、进料怎么加工 |
| 网页 / HTTP / MCP | **交付窗口**，把知识交给人、业务系统和 AI Agent |

## 平台现在长什么样（当前已具备）

从资料进到知识出，当前主链是：

```text
资料进入（网页上传 / 一张网切片接入）
  → 知识库存放（权限、版本、来源）
  → 挖掘流水线加工（解析 → 切片 → 表格 → 索引）
  → 检索交付（网页 / HTTP / MCP，三通道同一个引擎）
  → 维护（删除与恢复、增量重挖、快照生命周期）
```

已经具备的主体能力（引自 54 号文档"当前已经具备的基础"）：

- 知识库、目录、文件、归档包、文档版本、删除和恢复；
- 多类文档解析：标题、正文、列表、代码、公式、图片说明和表格提取；
- 文档、章节、切片、表格及其父子、顺序和包含关系；
- 关键词与语义召回、结果融合、重排和证据展开；
- 章节导航、上下文展开、表格查询和原始证据读取；
- 面向 Agent 的知识搜索、深入读取和受控资料写入基础能力。

## 运行形态

平台以**单容器 All-in-One**方式部署，一个容器里跑 6 个服务：

| 服务 | 容器内端口 | 职责 |
|---|---|---|
| nginx | 80（宿主机映射 **8080**） | 前端静态文件 + 统一代理入口 |
| knowledge_mining | 8901（仅回环） | 知识挖掘（解析、入库、生命周期） |
| llm_service | 8900（仅回环） | LLM 运行时（挖掘背后的模型调用） |
| main_control_service | 8910（仅回环） | 主控配置中心（登录认证、域路由代理） |
| agent_serving_java | 8081（仅回环） | 检索服务 |
| mcp_server | 9000（**全网绑定**） | MCP 服务（外部 Agent 直连入口） |

浏览器和脚本访问 `http://<服务器IP>:8080`（对外只有 8080 与 9000 两个口）；所有后端 API 统一经主控服务代理（详见第 30 章）。

## 平台要往哪去（建设中，不是现状）

按 54 号文档的演进规划，下一阶段是在现有主链上增加一条**知识制品闭环**：围绕高频业务任务，把反复进行的整理工作提前完成（如规格矩阵、对象卡、规则、方案方法），经专家校准后正式发布，供人和 Agent 直接使用。最小本体模块、制作 Agent 协作、试用与反馈机制属于这条线的组成部分。

**现阶段使用者接触到的全部功能**仍为：知识库管理、上传、挖掘、检索、MCP 接入、一张网接入与上述管理页。本指南用户篇只写已上线的功能。

## 三条最重要的边界（引自 54 号文档）

1. **能回原文**：每个关键事实知道来自哪里、用了哪个版本、当前是否还有权限和效力。
2. **能快速找到**：人和 Agent 能通过检索、章节、表格和对象关系发现需要的知识。
3. **能直接用于业务**：高频任务不必每次从零阅读和整理。

原始资料负责可信，挖掘与检索负责可找可读，知识制品（建设中）负责业务可用，真实使用反馈负责持续演进——四者互补，不是替代关系。
