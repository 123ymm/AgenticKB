# 41 · 日常运维

部署后的日常：看状态、重启服务、看日志、清理数据。**以下 docker/compose 命令均在仓库根目录执行**（compose 项目名与挂载锚定仓库根）。

## 容器与服务

```bash
docker exec cmkb supervisorctl status            # 6 服务状态（应全 RUNNING）
docker exec cmkb supervisorctl restart mining    # 重启单个服务
docker exec cmkb supervisorctl restart all       # 重启全部——注意：连带 nginx，页面会短暂掉线
docker compose exec app bash                     # 进容器
docker compose down / up -d                      # 停 / 启
```

服务名对照：`mining` / `llm_service` / `control` / `serving` / `mcp` / `nginx`。

## 日志

| 位置 | 内容 |
|---|---|
| `./logs/<服务>.log`（宿主机仓库根 logs/） | 各服务真实日志——**不在 docker logs 里** |
| `./logs/supervisord.log` | supervisor 生命周期日志 |
| `./logs/restart-orchestrator…` | 一键重启编排日志 |

```bash
tail -f logs/mining.log           # 实时跟踪
tail -50 logs/serving.log         # 最近 50 行
```

## 数据库日常

**工具用法（可执行形态）**：

```bash
# 看库状态：需要 PG 连接环境变量（值在 main_control_service/config/system/database.yaml）
docker exec -e PG_HOST=<host> -e PG_PORT=5432 -e PG_DBNAME=<库名> \
  -e PG_USER=<user> -e PG_PASSWORD=<密码> cmkb \
  python inspect_kb_state.py

# inspect_db.py / export_db.py 读仓库根 .env 的连接变量——服务器上该 .env 只有 serving 密钥时，
# 需临时补 PG_* 变量再跑，或改用上面 inspect_kb_state 的方式

# reset_db.py：连接配置读 database.yaml；默认只预览目标库和表，加 --execute 才实际执行
```

**reset_db.py 的防护与盲区**：默认预览模式、需显式执行；**不操作 MinIO、Docker volumes、主控 SQLite**——重置后对象存储里的字节会残留（脚本收尾也会打印 "MinIO object bytes and Docker volumes were not modified"）。**绝不对生产库使用**。

**备份**：数据库用 `export_db.py`（注意其 .env 连接依赖）；MinIO 对象与 `uploads`/`control_data` 两个 named volume 目前**没有自动备份**——需要备份策略时按卷目录另行安排（见第 42 章值守缺口讨论）。

## 观测要点（概览页，仅管理员）

- **检索次数掉 0** = 多为接入断了（密钥轮换/网络），不是没人用；
- **零结果率**与「答不上来的问题」清单 = 知识覆盖缺口的直接信号（补文档重挖）；
- **P95 延迟**与平均延迟差距大 = 长尾严重；
- **范式调用排行**里"未走范式（旧检索）"占比高 = 有流量没走范式引擎。
