# 42 · 故障排查：历史坑汇编

运维侧故障速查（用户侧问题见第 21 章）。每条注明出处文档。

## 部署与启动

| 现象 | 根因 | 处置 | 出处 |
|---|---|---|---|
| 前端 403 | 空 bind-mount 遮蔽产物（老镜像） | rebuild 镜像；或从镜像手动补齐宿主机目录（镜像自带 `/image-seed/` 种子自举） | 部署指南附3 |
| serving FATAL | `runtime/` 无 jar | 检查 `runtime/agent_serving.jar` 是否存在 | 部署指南附3 |
| 部署脚本停在 PG 校验 | Docker 子网未放行/账号错 | `pg_hba.conf` 放行 `172.30.30.0/24`；核对 database.yaml | 部署指南附3 |
| 端口冲突 | 8080 等被占 | 设 `CMKB_UI_PORT` / `CMKB_LLM_PORT` / `CMKB_MINING_PORT` / `CMKB_CONTROL_PORT` / `CMKB_SERVING_PORT` / `CMKB_MCP_PORT`（写服务器 .env 或 export） | 部署指南附3、compose |
| 某服务反复重启 | — | `tail -50 logs/<服务>.log`（**宿主机 ./logs/，不在 docker logs**） | 部署指南附3 |
| apply 卡在"输入 DELETE" | 迁移门禁要求人工确认删除轮换目标库 | 确认可删则输入 DELETE；无 TTY 环境改为人工执行带 `--replace-target` 的 migration apply | deploy-sync.sh 迁移门禁（第 40 章 A3） |
| 迁移失败服务停止 | 迁移回滚也未完成时服务保持停止 | 按提示人工介入（回滚日志在脚本输出） | deploy-sync.sh |
| Linux 执行 `.sh` 报 `$'\r': command not found` | Windows 直接拷贝的脚本是 CRLF | `sed -i 's/\r$//' *.sh`（git clone 得到的天然 LF 无此问题） | 部署指南附4 |
| compose 报怪错 | docker-compose.yml 被写成 CRLF | 同上处理 | 部署指南附4 |
| 同步后行为没变 | 没重启该服务 / Java 没重建 | 确认 apply 输出的重启清单；Java 走 pack 时先 `mvn package` | 部署指南 A |
| 误删了服务器 .env | 当成"废弃文件"清理 | `.env` 存 serving/mcp 内部密钥——从备份恢复或参照 deploy-server.sh 首次生成逻辑重建 | compose/deploy-server.sh |

## 服务与运行时

| 现象 | 根因 | 处置 | 出处 |
|---|---|---|---|
| 某服务健康检查不通过 | 3 秒探测超时按不健康处理 | 看该服务日志；修好后 supervisorctl restart | 概览页指标说明 |
| 全站打不开/登录报错 | PG 不可达或连接配置错误（PG 是业务事实源，故障会连带登录） | 核对 database.yaml 连通性与 pg_hba 放行；网络恢复后一键重启按依赖序拉起 | 30 章架构、部署指南附3 |
| 挖掘请求延迟数秒 | 请求路径里懒导入重模块占 GIL（历史案例：`mining.jobs.run` ~2.5s） | 已在 lifespan 预热；再出现先查是否又在请求路径懒导入 | 开发流程 §6 |
| 重启后挖掘任务没了 | 进行中的挖掘被重启中断 | 正常——由队列自动续挖（一键重启卡片语义） | ServiceRestartCard |
| 一键重启等待超时 | 编排卡住 | 看 `./logs/restart-orchestrator` 日志 | ServiceRestartCard |
| 挖掘大量失败伴"向量缺失" | LLM/嵌入端点不可用（llm_service.yaml 配的端点或密钥失效） | 看 `logs/llm_service.log`；修 llm_service.yaml 后按 D 路线重应用并重启 | 检索指南 §1、40 章 D |

## 检索与数据

| 现象 | 根因 | 处置 | 出处 |
|---|---|---|---|
| 大量请求结果比预期多 | 调用方没传 kbIds（不传=全部可见库，范围放大） | 调用方显式传 kbIds | KbAccessService（第 14 章） |
| 检索服务日志表不存在提示 | 检索服务从未启动过 | 页面显示"尚未产生检索日志"而非 0，属正常 | 概览页指标说明 |
| 中文 API 测试乱码 | Windows curl GBK | 请求体写 UTF-8 json 文件 `--data-binary @body.json` | 检索指南 §9 |
| 改算子后旧知识不变 | 哈希去重 SKIP 复用旧快照 | 重启 mining + 强制重挖 | 开发流程 §6 |
| table_row 爆量 | 已发布 manifest 冻结算子参数 | 域包策略覆盖或重新发布工作流 | 开发流程 §6 |
| 移动文件后状态永远未挖掘 | `document_key` 未同步（自写移动逻辑时） | 用页面移动；新逻辑必须同步 document_key | 开发流程 §6 |
| 外部 Agent 全断（连不上 9000） | 端口映射被改回回环 | compose 里 MCP 9000 **勿改回 127.0.0.1**（nginx 无 /mcp 转发，回环会切断内网客户端）；查防火墙放行 | docker-compose.yml 注释 |
| Java 测试假绿 | 增量编译 | `rm -rf target/classes target/test-classes && mvn -o test` | 开发流程 §2 |
| 前端类型检查假通过 | `vue-tsc --noEmit` 在 references-only 根 tsconfig 下为空检查 | 必须 `npm run build` | superpowers 计划 2026-09-17、53 号 |

## 值守场景缺口（现阶段如实告知）

以下场景**当前没有内建机制**，值守时按需自行安排：

- **备份/恢复**：数据库可 `export_db.py`/`import_db.py`；MinIO 对象与 Docker volumes 无自动备份（reset_db 的盲区声明印证了边界）；
- **监控/告警接入**：无 metrics 端点；可用健康检查 URL（`/health` 族）+ 概览页人工巡检替代；
- **HTTPS/证书**：当前 nginx 仅 HTTP，属部署形态决策——内网明文承载 JWT 与 MCP 密钥，边界由网络层保障；
- **磁盘增长**：uploads/MinIO 数据量无监控，需人工关注。

## 排查的通用顺序

1. `docker exec cmkb supervisorctl status`——哪个服务不 RUNNING？
2. `tail -50 logs/<服务>.log`——真实日志在宿主机 `./logs/`；
3. 网页「系统状态」健康探测 + 「服务日志」；
4. 数据面用 `inspect_kb_state.py` 看库状态（命令形态见第 41 章）；
5. 仍无解 → 按第 34 章档案索引找对应模块的审查/验收文档。
