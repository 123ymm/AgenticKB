# 知识制品 Pipeline 工作台需求文档

更新日期：2026-10-26

配套说明：[数据库表与字段说明](./知识制品-Pipeline工作台-数据库表与字段说明.md)，包含读写时机、JSON 字段结构、数据关联及只读排查 SQL。

本文统一描述本次知识制品设计态改造的需求、交互、数据规则及实现边界，替代此前的知识库导入阶段一、Pipeline 阶段一和完整验收文档。阶段性临时限制不再作为当前需求。

## 1. 背景与目标

原表格制品主要通过 Excel 上传、字段映射和发布形成资产。新增知识库来源，并将设计态改为可连续加工、回看和发布的 Pipeline 工作台。

目标：

1. 零码加工：运营通过“筛选输入 → 选择算子 → 配置参数 → 查看产物”完成制品加工。
2. 全链路追溯：保存每步的输入引用、算子版本、配置、输出和来源；支持恢复配置、回看结果及重新加工。模型重新执行不保证与历史结果逐字一致，历史快照用于准确回看。
3. 定版与回退：任意符合发布条件的步骤均可发布；回看历史后可以继续加工，保留原分支。
4. 大模型加列：基于已有列抽取或生成新列，支持试跑、全量执行和失败行重试。
5. 复用现有能力：沿用现有制品、知识库选择、算子注册、任务队列、对象存储和 LLM 服务。

## 2. 建设约束与范围

- 必须基于现有代码开发，不另建一套制品系统。
- 不修改数据库 schema，不新增表或字段；使用现有表、JSON 字段和存储接口。
- 中间结果不写入正式制品行、列及发布版本；用户确认发布后接入原有发布逻辑。
- “设计态不入库”指不写正式制品数据，并非完全不持久化：过程元数据写现有数据库，完整表格快照写 MinIO。
- 制品自身的创建、成员及权限仍沿用原有逻辑，不能将其理解为发布前完全不写 `kb_artifacts`。
- 原有 Excel 导入、运行态、成员管理、正式版本及版本回滚能力保留。
- 表格分类、同类合并是可选算子，不作为固定必经阶段。
- 工作台不重新解析原文档；起始抽取读取挖掘阶段已有的结果。
- 本次不建设多人实时协同表格、SQL 数据加工引擎或独立部署的表格任务服务。

## 3. 工作台布局与操作

### 3.1 三栏布局

| 区域 | 内容与职责 |
| --- | --- |
| 左栏：输入 | 起始步骤选择知识库目录/文件；后续步骤展示上一步完整产物的分页视图，支持筛选和保留列 |
| 中栏：算子加工 | 选择算子、配置参数、执行、查看状态；LLM 支持试跑和失败行重试 |
| 右栏：当前产物 | 展示当前步骤输出，查看完整单元格、来源和模型任务信息；人工修改产生新步骤 |
| 顶部右侧 | 历史/分支选择器、刷新、发布当前步定版 |
| 底部步骤条 | 当前分支的 step1、step2、step3 等，以及“下一步” |

### 3.2 按钮语义

- **执行表格抽取**：按已确认的来源创建起始任务。
- **执行完整输入**：处理完整输入中满足条件的数据，不仅处理当前页面的行。
- **下一步**：以当前查看步骤的产物作为输入，进入下一步配置；点击本身不执行算子、不生成输出快照。
- **发布当前步定版**：位于工作台右上角，打开当前步骤的发布配置；不能直接跳过预览和确认。
- **刷新**：读取最新状态，不重新执行加工。

### 3.3 回看与分支

1. 从 step3 点击 step1 只切换查看内容，底部仍保留 step1、step2、step3，并高亮当前步骤。
2. 用户可直接再次点击 step2 或 step3，查看对应输入、配置和产物。
3. 回看较早步骤后点击“下一步”，以该历史快照为输入；执行后形成新分支，原后续步骤保留。
4. 历史/分支选择器提供旧分支访问；选择其他分支时，底部展示对应分支链。
5. 刷新记录不能因当前查看的是较早步骤而截断底部步骤条。
6. 已保存步骤和快照可在重新打开页面后恢复；未执行的临时表单配置不承诺跨刷新保存。

## 4. 来源选择与起始算子

### 4.1 知识库来源选择

- 一次选择一个同域、当前用户有读取权限的知识库，可选择多个目录和文件。
- 复用现有目录递归选择、文件搜索、分页和去重能力；目录是否包含子目录由选择项控制。
- 切换知识库清空原选择；异步目录请求不得将旧知识库的选择重新写回。
- 确认来源仅确认文件清单，点击执行后才提交加工任务。
- 固定提交时的文档版本和对应可用解析快照，不自动使用其他内容版本的旧结果。
- 对未抽取、没有表格、投影不完整和读取失败分别给出原因，不能静默忽略。

### 4.2 起始输出字段

每张源表形成一行；同一文件包含多张表时形成多行。

| 字段键 | 展示名 | 规则 |
| --- | --- | --- |
| `directory` | 目录 | 来源文件目录 |
| `file_name` | 文件名 | 来源文件名称 |
| `file_content` | 文件内容 | 对应解析快照中的完整解析正文，可展开查看 |
| `table_name` | 表名 | 原文完整表标题，保留表号和产品型号 |
| `table_content` | 表格内容 | 整理后的 JSON 表格，格式见下文 |

### 4.3 表名规则

应得到完整标题，例如：

- `表1 PAC3KS54-NE基本属性`
- `表2 PAC3KS54-NE与产品型号的配套关系`

优先使用解析结果明确关联的标题；没有关联时，识别紧邻表格之前、可定位到该表的编号标题。不得跨越明确不同的页面关联标题，也不得把任意正文作为表名。

去掉标题外层 Markdown 展示标记，例如 `*标题*`、`**标题**`、`\*标题\*`，保留实际标题文字。无法找到标题时退回工作表名，再退回“未命名表 + 表引用”；不凭空生成业务标题。

### 4.4 表格内容格式

新抽取的 `table_content` 输出如下结构，不直接展示底层单元格坐标列表：

```json
{
  "表头": ["属性", "描述"],
  "数据": [
    {"属性": "描述", "描述": "3000W交流电源模块(黑色)"},
    {"属性": "部件编码", "描述": "02131712"},
    {"属性": "型号", "描述": "PAC3KS54-NE"}
  ]
}
```

整理规则：

- 按列顺序生成表头，按行顺序生成对象数组；表头单元格不作为数据行。
- 清除表头外层 Markdown 标记，数据对象的键与整理后表头一致。
- 保留原始单元格值，不把 `02131712` 自动转换成数字。
- 重复列名增加后缀，避免对象键覆盖；缺失单元格填 `null`，空表保留表头。
- 不改动源 `asset_table_cells` 数据；来源及表引用继续保留，原始坐标可由源表追溯。
- 新旧快照均需可加工；展开、合并兼容“表头/数据”、既有 `rows` 以及旧 `cells` 结构。
- 历史快照不自动重写；新格式和新表名规则通过重新执行抽取生成新快照。

## 5. 加工算子

| 算子 | 功能及约束 |
| --- | --- |
| 表格抽取 | 起始接入已有知识库表格及解析正文，不重新挖掘 |
| 筛选 / 保留列 | 对完整输入执行条件筛选与列选择，形成新快照 |
| 删除列 | 删除用户选择的业务列，至少保留一列；保留内部行标识和来源 |
| 字段改名 / 类型 / 排序 | 调整字段名称、类型及列顺序；排序指字段顺序，不是数据行排序 |
| 去重 | 根据选定字段去除重复行 |
| 展开表格 JSON | 将嵌套表格展开为业务行，可配置字段前缀，保留来源 |
| 表格分类 | 按表名归一化及字符序列相似度分组，允许配置阈值和调整分类 |
| 同类表格合并 | 根据分类列纵向合并表格记录，保留各行来源；不同字段可通过后续展开形成字段并集 |
| 关联对照表 | 上传 `.xlsx`，使用第一张工作表、首行表头，按键左关联补充列 |
| 人工调整 | 修改单元格生成新的加工步骤，不覆盖原快照 |
| 大模型加列 | 从指定输入列抽取或生成新列，明确输出字段、类型及加工要求 |

补充规则：

- 表名分类是名称相似度分组，不宣称具备语义聚类能力。
- 同类合并每类输出一行嵌套表格，不自动批量创建正式资产；若每类需要独立资产，可筛选后分别发布。
- 当前合并结果保留 `rows`、`row_sources` 内部结构；起始抽取的“表头/数据”格式不代表所有历史或算子结果已经统一重写。
- 对照表右侧关联键重复时拒绝执行；未匹配左表行保留，新增字段为空；公式需先转换为值。
- 所有算子输出均形成新快照，不能修改上一步快照或源知识库表格。

## 6. 大模型加列

1. 用户选择输入列，配置提示词、新列名称和类型，可选择模型或使用已有默认模型。
2. 提供前 5 行试跑；试跑结果不能直接发布或继续下一步，需返回原始输入执行全量。
3. 通过现有 `LlmTaskClient` 提交 Chat 任务，不增加工作台独立的 API Key 配置。
4. 当前逐行提交并等待结果；保存任务 ID、行状态和历史模型加工信息。
5. 对返回结果校验 JSON、所需字段和类型；失败行给出问题信息，不冒充成功结果。
6. 支持仅重试失败行，已成功行不再次调用模型；连续两次不同加列操作应分别执行。
7. 每 10 行及末行保存检查点，执行恢复可复用已完成请求。
8. 存在失败模型行时阻止发布；取消后停止后续加工，已经提交的模型请求可能仍完成。

## 7. 发布与正式版本

### 7.1 发布前提

- 当前步骤已完成，有可用输出，且不是试跑快照。
- 用户具备目标制品的相应权限；已有目标必须同域且为表格制品。
- 用户确认必要的问题提示并补充使用说明。

### 7.2 发布流程

1. 选择当前制品、同域已有制品或新建制品。
2. 配置字段映射、类型、主键和冲突策略；JSON 先展开，或明确选择按 JSON 文本发布。
3. 预览行数、示例和冲突；预览不写正式数据，不生成版本。
4. 确认发布，复用现有制品服务生成正式版本并保存步骤发布记录。

### 7.3 一致性与兼容性

- 合并已有资产沿用目标字段及主键，映射目标全部列，不借此隐式改变目标 schema。
- 目标存在未发布草稿时阻止合并；预览后目标变化必须重新预览。
- 主键冲突默认阻止，明确选择覆盖后才允许覆盖。
- 相同发布请求重复提交不能重复创建资产或版本；发布失败时正式数据、版本与发布记录共同回滚。
- 设计态删除列不等于删除已有正式资产的列；精简后的结构可以发布为新资产。
- 发布后继续使用原有运行态、Agent/MCP 查询和正式版本回滚能力。
- 工作台“回看/分支加工”与正式制品“版本回滚”是两种独立操作。

## 8. 数据、权限与执行边界

### 8.1 复用资源

| 资源 | 用途 |
| --- | --- |
| `asset_documents` 及现有文档快照、关联表 | 来源文件、版本及可用抽取结果 |
| `asset_structured_assets`、`asset_table_cells` | 只读源表和单元格 |
| `mining_workflows`、`mining_workflow_versions` | 步骤定义、算子配置及发布记录 |
| `mining_runs`、`mining_workflow_node_events` | 运行状态、父子关系、进度、租约及事件 |
| `asset_storage_objects`、MinIO | 中间表、对照表和检查点的存储引用与内容 |
| 现有制品行、列及版本表 | 确认发布后的正式数据和版本 |
| `kb_artifact_batches` | 保留用于原有导入链路，Pipeline 中间步骤不使用它模拟导入批次 |

不删除或宣布弃用任何现有数据库表。

### 8.2 快照与运行

- 每步保存完整输出，而不是仅保存相对上一步的差异。
- 每步创建单节点工作流及独立运行；`parent_run_id` 指向输入步骤，`step_index` 表示深度。同一父步骤可有多个子步骤。
- 通过 `profile=artifact_table` 接入原域任务队列，不进入普通文档挖掘的 `mining_finalize`、Build 和向量化检查。
- 快照包括列定义、行、文档正文映射、问题和来源；文档正文可集中存储，读取时补入文件内容列。
- `asset_storage_objects` 只登记 bucket、object_key、摘要、大小和状态；完整 JSON 保存在现有 binary bucket 的 `artifact-tables/v1/` 路径。
- 执行时加载快照到内存，完成后持久化；前端只持有页面数据，不承担完整结果的长期存储。
- 读快照时校验可用状态、大小和摘要；任务状态写入受租约及执行者身份保护。

### 8.3 权限与规模

- 服务端校验制品设计权限、来源知识库权限及同域约束，不能仅依赖按钮是否显示。
- 来源最多 2000 个文件；单个解析 JSON 或工作台快照上限 64MB；普通加工上限 100000 行、200 列。超限明确报错，不静默截断。
- 前端默认每页 20 行；分页不改变完整输入的加工范围。
- 当前后端为完整 JSON 快照内存加工，不是数据库分页计算；快照回收策略不在本次范围内。

## 9. 模块职责与调用关系

| 模块 | 职责 |
| --- | --- |
| `kb-ui` | 三栏工作台、步骤导航、参数表单、HTTP 请求、状态轮询和发布交互 |
| `knowledge_mining/mining/api` | 应用装配、复用域队列并分派表格任务 |
| `knowledge_mining/mining/kb` | 制品接口、权限、步骤组织、来源读取、快照持久化及发布桥接 |
| `knowledge_mining/mining/workflow` | 复用 HandlerRegistry，定义起始结构及表格算子变换 |
| `llm_service/runtime/service.py` | 通用 Chat/embedding/rerank 任务提交、模型选择、状态及结果查询 |

前端组件通过 `src/api/artifactPipeline.ts` 调用 `createProxyClient('mining')`，携带登录身份，经主控服务的域代理转发到 `/api/artifacts/{artifact_id}/pipeline`。

提交抽取或步骤接口返回 `run_id` 后，前端在活跃页面约每 2 秒查询运行和快照，完成后展示结果；回看只读取，不重跑算子。发布接口分 `confirm=false` 预览和 `confirm=true` 确认两次调用。

当前表格执行由 `ArtifactPipelineService.execute()` 驱动，不是将整条步骤链作为一个多节点图交给原 `WorkflowRuntime` 一次执行。

此前 `LLMService.submit_embedding()` 默认维度读取修复属于相关基础服务修复：显式请求维度优先，否则使用 `embedding.dimensions`。工作台大模型加列使用 Chat，不依赖该 embedding 调用路径。

## 10. 核心验收标准

| 场景 | 预期 |
| --- | --- |
| 选择目录和文件 | 去重正确，确认选择不执行；无权限来源不可读取 |
| 抽取原有表格 | 每张表一行，五列完整；异常文件有明确原因 |
| 表名与表格内容 | 保留完整编号标题；输出“表头/数据”格式，编码前导零保留 |
| 筛选与删除列 | 处理完整输入；不能删光所有列，历史快照不变 |
| 连续执行至 step3 后回看 step1 | step2、step3 仍在底部且可点击，刷新记录后仍保留 |
| 历史步骤点击下一步 | 点击时仅进入配置，执行后生成新分支，旧分支可回看 |
| 分类、合并与展开 | 可独立选择，合并后可展开并追溯原始来源 |
| 对照表关联 | 重复右键拒绝；未匹配左行保留 |
| LLM 试跑与失败重试 | 试跑不能发布/继续，重试不重复处理成功行 |
| 发布布局与预览 | 发布按钮位于右上角；预览不产生正式版本 |
| 确认发布 | 正式数据、版本及发布记录一致；重复请求幂等，异常回滚 |
| 重新打开页面 | 已保存步骤及结果可恢复，不自动重新调用模型或挖掘 |

真实模型鉴权、配额和输出效果须在实际环境试跑确认；自动化模拟测试不能替代真实模型验收。

## 附录：本地加载修改

在项目根目录构建并更新 Docker 静态前端：

```powershell
Set-Location D:\MyProjects\AgenticKB\kb-ui
npm run build
Set-Location ..
Copy-Item .\kb-ui\dist\* .\kb-ui-dist -Recurse -Force
```

后端源码修改后，当前本地源码挂载部署使用：

```powershell
docker compose exec -T app supervisorctl restart mining
docker compose exec -T app supervisorctl status mining
```

浏览器 Ctrl+F5。仅前端布局或文案修改不需要重启 mining；改变抽取规则后需重新执行抽取，已保存快照不会自动更新。本次无数据库迁移步骤。
