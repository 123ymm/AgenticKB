## 一、总原则（三句话）

1. **机制照抄表格**：设计态/运行态、发布快照、回滚、乐观锁、权限矩阵、批次流水、说明卡、MCP 转发——全部复用已上线实现，一处不改语义。
2. **存储按内容形态设计**：表格=行+jsonb（格按列名寻址）；wiki=页=frontmatter(jsonb)+正文(TEXT)+页间引用(边表)。正文永远不进 jsonb——正文是整篇文档，从不按键取值。
3. **wiki 是"隐藏知识库"**：发布后的页面进入检索体系——向量（页面单元 embedding）、关键词（正文匹配）、图（页间引用单跳）三条通道，以**制品域独立检索路径**实现（同构复用范式引擎里可抽取的公共部件；不把制品塞进范式引擎、不物理混入库侧检索单元表——两侧解耦、独立演进）。

## 二、存储层：数据表两边对比

### 2.1 通用表（复用，零改动）

| 表 | 现状 | wiki 接入 |
|---|---|---|
| `kb_artifacts` | `kind CHECK ('table','wiki')` 已含 wiki | 直接用 |
| `kb_artifact_revisions` | schema_json + row_count | 直接用；schema_json 存"目录树+术语表+页面清单"（61号 §13 预留位）；row_count 复用存**页数**（语义=条目数，不改列名） |
| `kb_artifact_members` / `mcp_key_open_artifacts` | 成员角色 / 钥匙开放子集 | 直接用（权限谓词完全不碰 kind） |
| `kb_artifact_batches` | 批次流水，channel ∈ ('upload','kb_import')，列偏 Excel | **通用化小迁移**：channel 枚举补 `wiki_compile`（预留 `sql_import`）；新增 `details JSONB` 装通道专属细节，file_name/sheet_name 保留兼容 |

### 2.2 新增通用表：来源绑定（表格与 wiki 共建，第三轮讨论定）

```sql
CREATE TABLE kb_artifact_sources (
    id          TEXT PRIMARY KEY,
    artifact_id TEXT NOT NULL,
    kb_id       TEXT NOT NULL,
    scope       JSONB NOT NULL DEFAULT '{}',   -- {"directories":[...]}；同库多目录一行搞定
    fingerprint JSONB NOT NULL DEFAULT '{}',   -- 最近一次编译/导入时的快照指纹（脏标记对比用）
    status      TEXT NOT NULL DEFAULT 'active',
    created_by  TEXT NOT NULL,
    created_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE (artifact_id, kb_id)
);
```

- 为什么通用：绑定语义（谁供数、增量范围怎么算、provenance 聚合、发布时私有库知情提示）与 kind 无关；两张平行绑定表必然漂移。
- 脏标记：详情页对比 `fingerprint` 与当前快照集，不一致亮"来源已变化"；更新=用户手动点重新编译（观测自动、动作手动，MVP 无后台任务）。

### 2.3 表格专有表（现状不动）

`kb_table_columns`（列定义）+ `kb_table_rows`（revision + row_key + data/provenance/conflicts 三 jsonb 分离）。

### 2.4 wiki 专有表（三张新增）

```sql
-- ① 页面主表：与 kb_table_rows 同构的 revision 语义，内容换成"文档"
CREATE TABLE kb_wiki_pages (
    artifact_id TEXT NOT NULL,
    revision    INTEGER NOT NULL,             -- 0=draft 工作区；N=发布快照（与表格行表同义）
    page_key    TEXT NOT NULL,                -- 页面身份 = 标题归一；[[]] 链接按它解析
    title       TEXT NOT NULL,                -- 展示标题
    page_type   TEXT NOT NULL DEFAULT 'topic'
                CONSTRAINT ck_wiki_pages_type
                CHECK (page_type IN ('topic','glossary','contradiction','open_question')),
    frontmatter JSONB NOT NULL DEFAULT '{}',  -- 结构化键值：编译器写 title/summary/tags，人工可加任意键
    body_md     TEXT NOT NULL DEFAULT '',     -- md 正文（含 [[]] 双链原样保留）
    origin      TEXT NOT NULL DEFAULT 'machine'
                CONSTRAINT ck_wiki_pages_origin CHECK (origin IN ('machine','manual')),
    provenance  JSONB NOT NULL DEFAULT '[]',  -- 来源账：[{kb_id, snapshot_id, unit_ids, 段落说明}]
    flags       JSONB NOT NULL DEFAULT '{}',  -- 质量标记（对应表格 conflicts 的位置）
    ordinal     INTEGER NOT NULL DEFAULT 0,
    updated_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_by  TEXT NOT NULL DEFAULT '',
    PRIMARY KEY (artifact_id, revision, page_key)
);
CREATE INDEX idx_wiki_pages_type ON kb_wiki_pages(artifact_id, revision, page_type);

-- ② 引用边表：图单跳 + 断链账 + 反向链接，一表三用
CREATE TABLE kb_wiki_page_links (
    artifact_id TEXT NOT NULL,
    revision    INTEGER NOT NULL,
    from_page   TEXT NOT NULL,                -- 源页 page_key
    to_page     TEXT NOT NULL,                -- 目标 page_key；目标页不存在 → status='broken'
    anchor_text TEXT NOT NULL DEFAULT '',
    status      TEXT NOT NULL DEFAULT 'valid'
                CONSTRAINT ck_wiki_links_status CHECK (status IN ('valid','broken')),
    PRIMARY KEY (artifact_id, revision, from_page, to_page, anchor_text)
);
-- 反向链接（谁指向我）= 同表反向查询（WHERE to_page=?），不建第二张表。

-- ③ 检索单元表：发布后生成的"隐藏知识库"载体（draft/rev0 不产生检索单元）
CREATE TABLE kb_wiki_page_units (
    artifact_id  TEXT NOT NULL,
    revision     INTEGER NOT NULL,            -- 只存发布版（≥1）
    unit_key     TEXT NOT NULL,               -- page_key，或分块后 page_key#s2
    page_key     TEXT NOT NULL,
    content_text TEXT NOT NULL,               -- 分块文本，前置页标题上下文
    embedding    VECTOR(1024),                -- 发布后异步生成；NULL=未就绪（不进 HNSW）
    embed_status TEXT NOT NULL DEFAULT 'pending'
                 CONSTRAINT ck_wiki_units_embed CHECK (embed_status IN ('pending','done','failed')),
    PRIMARY KEY (artifact_id, revision, unit_key)
);
CREATE INDEX idx_wiki_units_hnsw ON kb_wiki_page_units
    USING hnsw (embedding vector_cosine_ops); -- 与迁移 009 同模式同守卫（pgvector≥0.8、串行建）
```

### 2.5 内容模型对照（一句话说清差异）

| | 表格 | wiki |
|---|---|---|
| 内容单元 | 行（row_key = 业务主键拼接） | 页（page_key = 标题归一） |
| 结构化部分 | 整行都是（data jsonb，格按列名寻址） | 只有 frontmatter（jsonb） |
| 非结构化部分 | 无 | 正文 body_md（TEXT，整篇存取，从不按键取值） |
| 关系 | 无制品内关系（跨制品走对象层） | 页间引用边表（制品内自有） |
| 质量标记 | conflicts | flags + 边表 status='broken' + 矛盾/缺口两种专页 |
| 人工保护 | ——（人工改的行没有标记需求） | origin（machine/manual），重编译不碰 manual 页 |

## 三、版本与生命周期层：逐条对照

rev0 草稿区 / draft_open 旗标 / current_revision 指针 / 回滚拨指针 / discard 逃生门 / 两级确认删除 / usage_note 发布门禁 / expected_updated_at 乐观锁——**全部同义复用，零语义变化**。发布事务逐步对照：

| 发布事务步骤 | 表格（已上线） | wiki |
|---|---|---|
| FOR UPDATE + 乐观锁原子校验 | 同 | 同 |
| usage_note / no_pending_changes 门禁 | 同 | 同 |
| 版本号 = GREATEST(指针, 历史最大)+1 防回滚重发撞键 | 同 | 同 |
| 键归一（alias 旧键迁新键） | data 键迁移 | **不适用**（MVP 无页改名迁移，见 §3.1） |
| 复制定格 | rows rev0→N | **pages rev0→N + links rev0→N（两张一起复制）** |
| schema 快照 | active 列定义数组 | **目录树 + 术语表 + 页面清单**（编译工序④的产出定格） |
| 清 rev0 + 拨指针 + draft_open=FALSE | 同 | 同 |
| 事务外后置动作 | 重建类型化表达式索引 | **删旧版检索单元 → 生成本版单元（分块）→ 异步向量 → 卡片报 embedding 进度** |

### 3.1 页面改名口径（MVP）

改名 = 新 page_key 建页 + 旧页删除（diff 可见）+ 指向旧页的链接自动落 `status='broken'` 进质量账。**不自动改写正文里的 [[]] 文字**——那是"身份再解析工序"（59号五硬要求之一），二期做。

### 3.2 重编译与 origin 保护

- 编译/重编译只写 origin='machine' 的页；origin='manual' 的页一根手指不碰。
- 机器页与人工页同 page_key 冲突 → 进矛盾账，人裁决（保留谁的）。
- 手工编辑某 machine 页 → 该页 origin 翻 'manual'（此后归人工保护）。

## 四、生产层：编译管线工业级规格

| | 表格 | wiki |
|---|---|---|
| 主通道 | Excel 上传三步向导 | **编译管线**（绑定库目录 → 编译 → 产出进 rev0） |
| 批次 | kb_artifact_batches channel='upload' | channel='wiki_compile'，details 记参数+来源指纹 |
| 辅通道 | （未来 kb_import / sql_import） | （未来 md 直传 channel='upload'，页 origin='manual'） |
| 设计态编辑 | 列管理 + 单格/批量/行编辑 | 页面编辑器（md 正文 + frontmatter 表单）+ 建/删页 + 目录调整；**人工改过的页 origin 自动翻 manual** |
| 人工防线 | 公式注入拦截/类型 cast/主键禁改 | origin 保护 + 断链账 + 矛盾/缺口页 |

### 4.1 复用知识库已产出的资产（编译输入清单）

编译管线**只读**库侧 L1 产出，不调用挖掘 pipeline：

| 库侧资产 | 编译用途 |
|---|---|
| `asset_retrieval_units_v2` / `asset_raw_segments` | 取材原料：绑定范围内的切片文本 |
| `asset_retrieval_embeddings_v2` | 聚类向量：按快照集直接取，**零新增计算** |
| `asset_structure_nodes/edges`（文档结构图） | 目录生成的结构骨架输入——DeepWiki"启发式打分定系统"的现成对应物 |
| `asset_table_cells` / `asset_structured_assets` | 页内可引用的精确数值（"精确值回表格"）；MVP 仅作 provenance 引用，表格内嵌渲染=P1 |
| `asset_build_document_snapshots` | 绑定范围解析 + 脏标记指纹 |
| source locators（014 定位协议） | 页 provenance 回指原文 |
| llm_service 异步通道 | generation/embedding 调用**基建**（与挖掘共享基础设施，不共享管线） |

两个向量用途**分线**：编译聚类用库侧已有向量；检索用页面单元新算向量（发布后生成）。互不相借。

### 4.2 管线六步（细化，标注工业出处）

```
①绑定：kb_artifact_sources 选库+目录
②取材与聚类：范围内切片+向量直接用库侧的；聚类纯代码——增量指派（相似度阈值入簇/
   否则新种子、3+成员转正）、>100 拆、簇间相似>0.85 合、凝聚度低重聚【Beever Atlas】
③目录生成（LLM）：产出目录树+术语表 → 【人工确认步——目录错全书废，DeepWiki 最大实证】
④簇级写作（LLM，异步 generation，25 页/批）：每页带全局目录上下文；
   批间约束注入（前批断链/无据规则以自然语言注入后批提示词）【LLM-Wiki Error Book 五段生命周期】
⑤链接与质量：抽 [[]] 生成 links（断链标 broken）；跨页矛盾 → contradiction 页；
   缺口 → open_question 页【bobs-big-brain：矛盾/缺口为一等页面类型】
⑥产出全部落 rev0（origin='machine'），进人工修订
```

### 4.3 页面格式规范（产出物标准）

**topic 页固定 schema**（LLM-Wiki 论文口径，四节结构）：

```markdown
---
type: topic
aliases: [别名1, 别名2]        # 参与链接解析：[[别名]] 也命中本页
tags: [标签]
created: 2026-10-21T10:00:00Z
updated: 2026-10-21T10:00:00Z
---
# 页标题
> 一句话摘要（blockquote，必填）

## 核心事实
- 事实句一 [[src:U10231]]
- 事实句二 [[src:U10231]] [[src:U10877]]

## 相关页面
- [[另一页key]] -- 关系注释（父子/组成/参照）

## 来源
- [[src:U10231]] -- 切片摘要一句话
```

- frontmatter 标准键：`type/aliases/tags/created/updated`；人工可加任意键（存 frontmatter jsonb）。
- `[[]]` 双链按 page_key **或 alias** 解析；`[[src:unit_id]]` 是引用标记（不是页面链接）。
- 阅读器把 `[[src:...]]` 渲染为可点击角标，回跳库切片原文（A1 定位协议）。

**专页 schema**（bobs-big-brain 口径，frontmatter 严格校验）：

| page_type | 专有 frontmatter 字段 | 正文必含节 |
|---|---|---|
| glossary | term, definition_source | 定义、用法、来源 |
| contradiction | claim_a, claim_b, source_a, source_b, severity(low/medium/high) | 双方主张（各带原文引用）、分析、裁决（人工填） |
| open_question | question(以?结尾), priority(low/medium/high), suggested_sources | 问题、上下文、建议补材来源 |

### 4.4 引用规范（两层，缺一不可）

1. **结构化 provenance（页级，硬性）**：每页 provenance jsonb 非空，回指 `{kb_id, snapshot_id, unit_ids[]}`——这是机器可查的来源账，发布时聚合做私有库知情提示。
2. **行内引用标记 `[[src:unit_id]]`（生成期强制+校验期确定性检查）**：
   - 生成 prompt 强制每个事实句带引用；
   - 发布前确定性校验三项（LLM 只复核，不判存在性——LLM-Wiki 铁律）：引用的 unit_id **存在于绑定范围**（悬空引用入账）；`[[]]` 页面链接**目标存在**（否则 links.status='broken'）；**密度检查**——连续 ≥3 个事实句无引用 → 页 flags 告警（TheKnowledge 的 claim-grounding+density lint 口径，告警不阻断）；
   - **draft 宽免**：人工新建未完成页 flags 标 `draft`，密度规则降级为静默。

### 4.5 质量账（Error Book 的 MVP 形态）

三本账合一查询视图：`links.status='broken'`（断链）+ `pages.flags`（密度/类型问题）+ contradiction/open_question 专页。
批间约束注入 = LLM-Wiki 五段生命周期（Discover→Attribute→Constrain→Inject→Verify&Close）的 MVP 轻量版（同一轮编译内生效）；跨轮持久 Error Book（约束规则库跨编译复用）= P1。

### 4.6 工程底座

25 页/批；幂等（page_key 稳定+UPSERT）；编译任务走异步通道+批次进度端点（复用 batch-status 形态）；分批失败仅重试失败批；内容哈希跳过未变簇=P1。

## 五、检索与消费层：wiki = 隐藏知识库

### 5.1 三个管线的分界（谁干什么，先说死）

| 管线 | 所属域 | wiki 是否使用 |
|---|---|---|
| 挖掘 pipeline（L0→L1：切片/向量/入库栅栏/readiness） | 知识库域 | **不使用**——编译只读库侧已产出的 L1 资产（§4.1） |
| 编译管线（§四） | 制品域 | 新建 |
| 检索范式引擎（operator 管线，KB 范围解析+dense/keyword/fusion 算子） | serving/知识库域 | **不进入**——范式引擎保持纯 KB 域，零改动 |

`kb_wiki_page_units` 的生成 = **发布事务的后置投影**（制品服务自己分块写入，轻量、同步），不是挖掘 pipeline。向量生成调用 llm_service embedding 异步通道——共享的是**基础设施**（模型/队列/重试/batch-status），不是挖掘管线本身。

### 5.2 检索架构决定：制品域独立检索路径（同构，不耦合）

- **表格 = 结构化定制检索**（art_ DSL 行/聚合查询，现状不动，终态）。
- **wiki = 制品域自己的检索服务**（`ArtifactWikiSearchService`，Java 侧）：固定三通道 dense + keyword + fusion，形态由 kind 定死，无需按库配置管线。
- **复用的是可抽取的公共部件，不是引擎**：HNSW 查询 SQL 模式（与 searchDenseV2 同构：ANN + `embed_status='done'` 过滤 + force_custom_plan 口径）；融合打分（现有 fusion 算子可抽工具类则复用，不可抽则同构实现）；`LlmServiceReranker` 预留（MVP 不开重排）；dense 降级复用 `denseVectorDegraded` 口径（向量未就绪该通道降级不失败）。
- **为什么不进范式引擎**：范式引擎带着按库配置、readiness 门禁、离线切换轮换这些 KB 域语义；制品塞进去两侧都被迫感知对方。wiki 检索形态固定，独立路径最简且两侧可独立演进。search_knowledge（库检索）因此看不到 wiki——wiki 检索只从制品入口进。
- **不把 wiki 页物理写进 `asset_retrieval_units_v2 / embeddings_v2`**（同一结论的另一半）：那两张表挂在挖掘栅栏/轮换/统一硬删管线上，混入制品页互相污染。

### 5.3 存储与切片口径（存储永不切片，切片只在投影层）

- `body_md` = **整页 md 原文**，一页一行，TEXT。人工编辑、阅读、导出都操作整页；存储层永远不知道"块"的存在。
- 切片只发生在**发布投影**：生成 kb_wiki_page_units 时页面级为主，超长页（>2000 字）按 H2 分块，块文本前置页标题上下文。
- 每次发布**重建**该版单元：删该制品旧版单元 → 写入新版 → 异步算向量。人工编辑只改页；重新发布后检索单元自动跟上，不存在"改了页但搜不到"的漂移。

### 5.4 消费入口对照

| 入口 | 表格 | wiki |
|---|---|---|
| 说明卡（发现） | get_knowledge art_ 无 query → 卡片 | 同（卡片字段：kind/page_count/embedding 进度） |
| 内容读取 | DSL：where/select/order/cursor 行查询 | **页面整读**（page_key → frontmatter+正文+溯源） |
| 向量检索 | 无（结构化查询即终态） | **有**：页面单元 HNSW |
| 关键词检索 | DSL 精确条件 | **有**：正文匹配 |
| 图查询 | 无 | **有**：links 单跳（正向链接+反向被链） |
| MCP art_ 分支 | query=DSL | 按 kind 分流：page 读取 / search / links 单跳 |

### 5.5 权限与可见性

- 检索/读取只看 **published** 版（current_revision）；rev0 对 Agent 永远不可见（与表格同一铁律）。
- 权限谓词整块复用（成员/owner/public/钥匙开放子集/404 反探测）。

### 5.6 检索入口清单（MVP）

web 制品详情页内搜索框；REST `/api/v1/artifacts/{id}/wiki/search|page|links`；MCP get_knowledge art_ 分流。跨制品全局搜索=未来。

## 七、MVP 边界与验收

**做**：编译管线（六步含目录确认步）、页面编辑器、阅读器、检索单元+三通道+图单跳、来源绑定+脏标记、origin 保护、矛盾/缺口页、批次与发布/回滚全套。

**不做**：md 直传通道（表结构已预留）、SQL 导入、增量编译/候选合并（整本重跑+diff）、页面改名身份迁移与正文链接自动改写、跨制品全局搜索、对象层挂载（等 L2 阶段1）、富文本编辑器。

**验收**：
1. 丢事实率（抽检 20-50 真实问题，wiki vs 原文对照）；
2. 重跑稳定性（同语料重编译，machine 页 diff≈0）；
3. 检索三通道全通：发布后 dense/关键词/图单跳各验一例；非成员 404；向量未就绪时 dense 降级不报错；
4. 版本机制回归：发布/回滚/discard/乐观锁 用例与表格同构通过；
5. origin 保护：人工改过的页重编译后内容不变；
6. 引用规范：发布的页 provenance 全部非空且 unit_id 存在于绑定范围；断链全部入账；密度告警生效；
7. 人工编辑闭环：改页→origin 翻 manual→重编译不丢→再发布后检索单元自动更新（改完能搜到新内容）。

**规模上限**：单库+可选目录；≤200 页/本（管线按 25 页/批校准）。
