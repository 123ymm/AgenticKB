# domain 解耦与 MCP 多钥匙化设计（三批次）

> 版本：V1.0
> 日期：2026-09-17
> 目的：把 domain 收敛为「数据归属 + 未来分库单元」两件事；建立用户↔domain 绑定；MCP 改为一人多把的「单域钥匙」；知识制品与 domain 解耦。按批次 1→2→3 实施，每批独立验收、独立回滚。
>
> 定案来源：2026-09-17 设计讨论（六项决策 + 三项微决策 + 迁移兜底修正）。现状均为代码核实事实，证据见附录 A。

## 一、背景：从公共图书馆到私人书房

现状（已核实，附录 A 有证据）：

- 所有登录用户可见全部 domain；域列表接口甚至**免鉴权全量可读**；
- 任何登录用户可在**任意** domain 建库，无域级授权；
- `visibility=public` 的库**全站可见，不分域**；
- MCP 一人一把钥匙（`mcp_access` 表主键即 `user_id`），开放库可跨域勾选，运行时由 `resolve_domain()` 推导域；
- 挖掘/检索范式已是全局定义 + 库级绑定——**现状即目标，不动**。

目标模型：

| 角色 | 定位 |
|---|---|
| domain | 数据归属地 + 未来分库单元，**仅此两件事** |
| 用户↔domain | admin 建 domain 并分配绑定；一人可绑多域；**不引入域管理员** |
| KB | 只能建在绑定域；跨域完全隔离（public 收敛为域内可见） |
| 范式 | 全局定义、库级热绑定，与 domain 无关（维持现状） |
| MCP | 用户级资产，**一人多把**，每把绑定**一个** domain，只能开放该域的库 |
| 知识制品 | 与 domain 解耦，绑「资料范围 + 负责人」（50 号文档同步修订） |
| LLM 服务 | 公共服务，domain 仅为记账标签（不动） |

## 二、定案记录

| # | 决策点 | 定案 |
|---|---|---|
| D1 | domain 创建与归属 | 维持现状：仅 admin 建 domain（`POST /api/v1/domains`）。新增用户↔domain 绑定表，admin 分配；一人可绑多域 |
| D2 | public 库可见性 | 收敛为**域内 public**：只对绑定该域的用户可见，跨域隐身 |
| D3 | MCP 跨域检索 | 不允许跨域。创建 MCP 时**选定一个 domain**，只开放该域下的库（单域钥匙） |
| D4 | 域主权 | 不引入域主人/域管理员，维持站点 admin + 普通用户两档 |
| D5 | 实施切分 | 方案 A 三批次：域绑定与隔离收敛 → MCP 多钥匙化 → 收尾 |
| D6 | 表结构同步 | 沿用现有「启动全量重放 + IF NOT EXISTS」机制，遵守第七节 DDL 家规 |

微决策（默认采纳，可推翻）：

- M1 存量迁移自动补绑：用户绑定集 = 名下有库（owner/member）的所有域；**兜底域从数据库推导，不写死**（见 4.2）；
- M2 MCP 钥匙软上限：每用户 10 把，需要更多找 admin；
- M3 工具 `domain` 参数保留但降级为**校验参数**：不传 = 钥匙域；传了必须等于钥匙域，否则报错（兼容存量 Agent 提示词）。

## 三、三条铁律

1. **domain 只做两件事**：数据归属 + 未来分库单元。权限、范式、MCP、制品一律不挂 domain。
2. **权限只有两层**：站点 admin + 库级 owner/editor/viewer/public。用户-域绑定只决定「看得到哪些域、能在哪建库」，不发明第三套权限体系。
3. **MCP 钥匙 = 用户签发给 Agent 的授权书**。所有工具的范围从钥匙推导；domain 是配置时声明的属性，不是运行时推导的权限。

## 四、批次 1：域绑定与隔离收敛（权限地基）

### 4.1 数据模型

新增一张表（放 `databases/kb/schemas/` 新编号文件，随 kb schema 既有执行路径生效，需登记进 `pg_schema.py` 清单）：

```sql
CREATE TABLE IF NOT EXISTS user_domains (
    user_id  TEXT NOT NULL,
    domain   TEXT NOT NULL,   -- registry 合法域，应用层校验（同 knowledge_bases.domain 风格）
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    PRIMARY KEY (user_id, domain)
);
```

### 4.2 存量迁移（修正版：兜底域从数据推导）

- **有库用户**：绑定集 = 名下有 owner/member 关系的库所在的全部域——纯数据推导（查 `knowledge_bases` + `kb_members`）；
- **无库用户**：兜底域取**当前 KB 数最多的域**；迁移脚本提供 `--fallback-domain` 参数显式覆盖；
- **admin 用户**：不写绑定行（admin 免绑定全通）；
- **新用户**：创建用户时自动绑定 registry 的 `default_domain`（运行时读配置值，不写死具体域；admin 改 registry 即改默认归属）；admin 可随时调整绑定。「零绑定用户」不允许存在——看不到任何域、无法建库的状态视为缺陷；
- registry 的 `default_domain`（当前 `cloud_core_network`）只是运行时「未显式指定 domain」的兜底配置，**与存量迁移无关，不做任何假设**；仅新用户自动绑定读它；
- 迁移幂等：`INSERT ... ON CONFLICT DO NOTHING`，可重复执行。

### 4.3 行为变化

| 点 | 现状 | 改为 |
|---|---|---|
| 域列表 `GET /api/v1/domains` | 免鉴权全量读 | 需登录；普通用户 = 绑定域，admin = 全量。main_control 无库，经服务间 HTTP 问 mining 取绑定集过滤；**mining 不可达时返回 503，不降级到全量**（安全优先） |
| admin 分配 | 无 | mining 新增 `POST /api/kb/admin/users/{id}/domains`（批量覆盖式，body 为域列表）；**结果集为空 → 422 拒绝**（不允许制造零绑定用户）；解绑见 5.4 联动 |
| 建库 `_validate_domain` | 仅校验域合法 | 追加：非 admin 用户，domain 必须 ∈ 其绑定域 |
| public 库可见性 | 全站 | 域内：mining **全部 public 谓词**（`list_visible` / `list_visible_kb_ids` / `is_visible` / `document_readable_by_user`——最后一个函数内两张查询各一处）与 serving `selectAccessibleKbIds` 的 public 分支统一加「kb.domain ∈ 用户绑定域」。**跨服务可见性谓词全处同步铁律：开工先 grep 计数对齐，漏一处即留越权口子** |
| 删域 `delete_domain` | 不校验域下有库 | 域下有 KB → 409 拒删，提示先迁库 |

可见性判定最终形态（mining 与 serving 语义对齐）：

```
可见 = site admin
     ∨ KB.owner = 用户
     ∨ 用户 ∈ kb_members
     ∨ (KB.visibility = 'public' ∧ KB.domain ∈ 用户绑定域)
```

owner/member 分支**不分域**（自己的库不因解绑而消失，这是有意的安全网）。

**serving（Java）侧获取绑定集的方式（定死，避免实现分叉）**：直读 `user_domains` 表——与现有 `kb_users` / `kb_members` 同库、同 mapper 访问路径，在 `selectAccessibleKbIds` 的 public 分支里加子查询 `kb.domain IN (SELECT domain FROM user_domains WHERE user_id = …)` 即可。**不新增服务间 HTTP 依赖，不往 JWT 里塞域列表**。main_control 域列表过滤走 HTTP 问 mining（见上表），两者路径不同是有意的：serving 本来就直读 kb 库。

### 4.4 前端

- 域选择器数据源自动收窄（列表接口已过滤），无需改组件逻辑；
- admin 用户管理页新增「域分配」控件（多选 + 保存）。

### 4.5 验收门禁

1. 普通用户：看不到未绑定域；看不到未绑定域的 public 库；不能在未绑定域建库（明确报错）；
2. admin：全量域可见、任意域建库、可分配/解绑；
3. owner 对未绑定域的自己库仍可见、仍可管理（owner 分支不分域）；
4. 存量迁移后每个非 admin 用户至少绑定一个域；迁移报告列出每人绑定集；
5. E2E：迁移前后登录态无感知（自己的库都在）。

## 五、批次 2：MCP 多钥匙化（单域钥匙）

### 5.1 数据模型与迁移

```sql
CREATE TABLE IF NOT EXISTS mcp_keys (
    id         TEXT PRIMARY KEY,
    user_id    TEXT NOT NULL,
    name       TEXT NOT NULL,          -- 用户自定义名称
    domain     TEXT NOT NULL,          -- 必须 ∈ 该用户绑定域（服务端强校验）
    key_hash   TEXT NOT NULL,          -- sha256，同现状
    key_prefix TEXT NOT NULL,          -- 前 8 位，界面识别
    status     TEXT NOT NULL DEFAULT 'active',   -- active / revoked
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    rotated_at TIMESTAMPTZ,
    last_used_at TIMESTAMPTZ,          -- 验钥时更新（沿用旧 mcp_access 语义）
    UNIQUE (user_id, name),
    FOREIGN KEY (user_id) REFERENCES kb_users(id) ON DELETE CASCADE
);
```

- `mcp_open_kbs`：PK `(user_id, kb_id)` → `(key_id, kb_id)`，且校验 `kb.domain = key.domain`；
- 010 配置表（open_tools / instructions / 工具描述）：从挂 user_id 改挂 key_id；
- **存量迁移**：旧 `mcp_access` 单行 → 用户的第一把钥匙（name=`default`）；绑定其当前开放库覆盖的**第一个域**（「第一个」= 开放库数量最多的域，并列时域名字典序，与 4.2 兜底逻辑同构），仅保留该域内的开放库勾选；迁移脚本输出被丢弃的跨域勾选清单，供用户重建；迁移幂等：**按 key_hash 已存在跳过**（跑两遍不产生第二把）；
- **在途上传票据处置**：迁移时全部作废——票据本就 ≤10 分钟、单次使用，Agent 按既有文档「票据超时重调工具取新 URL」自愈，无需兼容旧票据校验路径；
- 钥匙数量软上限 10 把/用户（M2）；
- 旧 `mcp_access` 表迁移后废弃（保留一个批次周期后删）。

### 5.2 服务端改造

- `mcp_server/identity.py`：验钥返回 `(user, key, key.domain, key 开放库 ∩ 实时权限)`；**`resolve_domain()` 推导逻辑整体退役**——钥匙自带域；
- 上传一次性票据：绑定从 `(kb_id, user_id)` 改为 `(kb_id, key_id, user_id)`——票据即凭证，吊销钥匙即吊销其票据权限；
- 密钥轮换/吊销语义不变（轮换 = 覆盖 hash，旧钥立即失效），作用域从用户级变为钥匙级。

### 5.3 三工具语义（运行时逻辑几乎不动，只换范围源头）

| 工具 | 变化 |
|---|---|
| `search_knowledge` | 范围 = 钥匙的开放库（原为用户开放库）；`domain` 参数保留为校验参数（M3）：不传 = 钥匙域，传了必须相等否则明确报错 |
| `get_knowledge` | 同上；顶层浏览（kb_tree）天然只显示钥匙域的库 |
| `upload_document` | 目标库必须属钥匙域（开放库勾选已保证）；票据验钥匙；自动挖掘照旧走库自己的 domain，不变 |

### 5.4 解绑联动

admin 将用户从某域解绑时：该域上的所有钥匙标记 `revoked`（或调用时报 `domain_not_bound` 明确错误，前端提示重新选域）——**不静默可用**。采用「调用时报错 + 列表页标失效」组合：解绑不主动改钥匙状态（可逆），但调用链路实时校验绑定。

### 5.5 前端

`McpAccessView` 从单卡改「钥匙列表」：

- 列表：名称 / 域 / key_prefix / 状态 / 创建时间；
- 每把钥匙独立配置：名称、域选择器（仅该用户绑定域）、该域开放库勾选、三工具开关（search/get/upload）、提示词 instructions、逐工具描述、接入配置 JSON（generic/Dify）、轮换、吊销；
- 创建/轮换时明文仅显示一次（沿用现状交互）。

### 5.6 验收门禁

1. 一把钥匙一个域：创建时选域，开放库只能勾该域（服务端强校验，前端只是辅助）；
2. 存量钥匙迁移后：原本单域的 Agent 无感；原本跨域的收到明确报错（附被丢弃勾选的迁移报告）；
3. 解绑域后，该域钥匙调用立即失败并给出人话错误；
4. 票据：A 钥匙申请的上传票据，吊销 A 后立即失效；
5. E2E：两把不同域的钥匙分别检索各自域的库，互不可见。

## 七、横切约束

### 7.1 DDL 家规（沿现有机制，缺一不可）

1. 新 SQL 文件一律 `CREATE TABLE IF NOT EXISTS` / `ADD COLUMN IF NOT EXISTS` / `CREATE INDEX IF NOT EXISTS` 风格；约束变更用 advisory 锁 + `DROP ... IF EXISTS` 再 ADD；
2. **每个新文件必须登记进 `pg_schema.py` 的显式清单**（漏登记 = 永不执行）；Java 侧如涉及须同步 `SCHEMA_SCRIPTS`；
3. 数据回填型迁移（如 4.2、5.1 的存量迁移）写成**幂等脚本**（ON CONFLICT DO NOTHING），可重复执行并输出报告。

### 7.2 部署

- 三批均含 `databases/` 变更：`deploy-sync.sh apply` **只拷文件不重启**，apply 后必须重启 mining（批次 1 public 可见性涉及 serving SQL 映射，同步重启 serving）——管理员一键重启按钮覆盖，部署清单注明；
- 每批独立分支、独立验收，失败回滚整批，不带病进下批。

**各批次回滚故事（具体裁定）**：

- 回滚通用动作 = 代码回退 + 重启；新表（`user_domains` / `mcp_keys`）**保留不删**——IF NOT EXISTS 幂等，旧代码不读它们，无副作用；
- **批次 1 回滚**：`user_domains` 数据留在库里，可见性/建库回到「全域 public、任意域建库」旧语义；重新上线批次 1 时迁移脚本幂等重跑即可；
- **批次 2 回滚**：分两个时间窗裁定——
  - 迁移后、**尚未有用户创建新钥匙**：干净回滚，旧 `mcp_access` 行未被破坏（迁移是搬移+保留旧表一个周期），旧路径直接可用；
  - 已有新钥匙/新勾选写入 `mcp_keys`：回滚 = 数据损失裁定——迁移后新创建的钥匙丢失，各用户的旧 `mcp_access` 行仍可恢复原路径（迁移不删旧表）。此损失显式可接受：钥匙可重建，明文本来就不存；
  - 因此批次 2 验收门禁要求**在放量（通知用户用新功能）之前**完成回滚演练。

### 7.3 不动清单（防止过度工程）

两套范式表、KB 内部文档/挖掘管线、llm_service 的 domain 标签、同域快照共享池、域级挖掘队列（域内串行跨域并行）、serving 共库回落逻辑、JWT/站点角色体系。
