# 表格知识制品 MVP 设计

> 编号：61号
> 版本：V1.0
> 日期：2026-10-16
> 定位：59号五阶段路线的**快赢切片**（表格制品先行，不等对象层）+ 60号制品层设计的**首个落地实施设计**。
> 范围声明：第一阶段 = **用户上传 Excel 端到端跑通**（创建→导入→编辑→发布→Agent 消费→迭代）。聚类发现、知识库导入、LLM 抽取、数据库直连全部不做，但表结构与流程为其预留接入口（§十三）。
> 讨论过程：2026-10-15/16 多轮逐概念过审（用户草稿→对抗审查→jsonb 路线→权限修正→版本机制确认）。

## 一、范围

### 1.1 做什么（MVP 三大块）

1. **制品生命周期**：增删改查、设计态/运行态、发布与版本控制（快照式）、回滚、停用。
2. **制品权限**：挂 domain、域内独立成员制（owner/editor/viewer）、MCP 权限由密钥→用户→制品角色派生。
3. **表格制品**：Excel 上传（三步向导：建表模式/追加上传模式）、schema 管理、数据编辑（单格/批量/追加）、发布 diff 预览、Agent 消费（artifacts 说明卡视图 + st_ 结构化查询）。

### 1.2 明确不做（MVP 边界）

| 不做 | 处理 |
|---|---|
| 知识库表格导入/聚类发现（子场景1） | 表结构预留（batches.channel 枚举含 kb_import），第二阶段接 |
| LLM 抽取表格（子场景2） | 同导入向导换来源，P1 |
| 指定数据库直连导入 | P2（依赖冻结+安全面） |
| 行列转换 | 砍（场景不明） |
| 试用态（trial）+评测门禁 | 发布即生效，评测门禁后续挂 A4 |
| 细粒度撤销栈 | 兜底语义=发布点即存档点（§4.4） |
| 物化视图/分区/delta 存储 | 量级触发时优化，查询语义不变 |
| Excel 导出、MCP 独立授权表、按角色分组可见性 | 后续 |

## 二、核心机制总览

```
┌────────────────────────────────────────────────────────┐
│ 制品（kb_artifacts，挂 domain）                          │
│   status: draft → published → deprecated                │
│   current_revision: 指针（0=从未发布）                    │
├──────────────┬─────────────────────────────────────────┤
│ 设计态        │ 运行态                                    │
│ 行存 rev0 槽位 │ 行存 rev N（发布快照，只读）              │
│ schema 活表   │ schema 定格在 revisions.schema_json       │
│ 随便改无历史   │ Agent/MCP 只读指针指向的 revision          │
└──────────────┴─────────────────────────────────────────┘
版本机制（快照式 copy-on-write）：
  发布 = 行复制 rev0→N+1 + schema 快照 + 建索引 + 清空 rev0 + 拨指针
  编辑 = ensure_draft()：rev0 不存在则先 checkout（current→rev0）
  回滚 = 拨指针（数据不动，瞬时）
  丢弃 = DELETE rev0
```

三条铁律（来自 60号，本设计遵守）：

1. **行地址 = (制品, 业务主键 row_key)**，禁止行号当身份（ordinal 仅展示排序）。
2. **业务值与来源账分离**：data 只放业务列；知识库/文档/章节/表名等来源信息放 provenance，永不混入 data。
3. **schema 单调扩展**：加列不动存量数据、删列软删、改名走 alias，运行态永远读发布时定格的快照。

## 三、数据库设计（六张表）

> jsonb 分布原则：**"内容"用 jsonb（形状随制品变），"治理"用普通列（形状固定且要约束力）**。6 张中 4 张含 jsonb（artifacts 的已在权限修正中删除，剩 revisions/columns/rows 含）、2 张纯普通列（batches/members）。

### 3.1 `kb_artifacts`（制品登记——制品维度）

```sql
CREATE TABLE kb_artifacts (
  artifact_id      UUID PRIMARY KEY,
  domain_id        TEXT NOT NULL,                 -- 唯一归属 domain（跨库组装的制品也在一个 domain 下）
  kind             TEXT NOT NULL CHECK (kind IN ('table','wiki')),  -- wiki 预留
  title            TEXT NOT NULL,
  description      TEXT NOT NULL DEFAULT '',      -- 说明卡：是什么
  usage_note       TEXT NOT NULL DEFAULT '',      -- 说明卡：何时用/何时不用（发布必填）
  owner_user_id    TEXT NOT NULL,                 -- 创建者（自动 owner）
  status           TEXT NOT NULL CHECK (status IN ('draft','published','deprecated')),
  current_revision INTEGER NOT NULL DEFAULT 0,    -- 运行态指针；0=从未发布
  created_at       TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at       TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_kb_artifacts_domain ON kb_artifacts(domain_id);
```

> 设计变更记录：原设计的 `source_kbs JSONB`（来源库数组+权限钳制）已删除——权限与库解绑（§5.1），来源信息由 provenance 承载（发布时聚合做知情提示）。

### 3.2 `kb_artifact_revisions`（发布快照——制品维度）

```sql
CREATE TABLE kb_artifact_revisions (
  artifact_id    UUID NOT NULL,
  revision       INTEGER NOT NULL,
  schema_json    JSONB NOT NULL,     -- 该版 schema 整体快照（表格=列定义数组；wiki 将来=页面清单）
  row_count      INTEGER NOT NULL,
  change_summary TEXT NOT NULL DEFAULT '',
  published_by   TEXT NOT NULL,
  published_at   TIMESTAMPTZ NOT NULL DEFAULT now(),
  PRIMARY KEY (artifact_id, revision)
);
```

### 3.3 `kb_artifact_members`（成员权限——制品维度）

```sql
CREATE TABLE kb_artifact_members (
  artifact_id UUID NOT NULL,
  user_id     TEXT NOT NULL,
  role        TEXT NOT NULL CHECK (role IN ('owner','editor','viewer')),
  PRIMARY KEY (artifact_id, user_id)
);
```

### 3.4 `kb_artifact_batches`（导入批次——制品维度）

```sql
CREATE TABLE kb_artifact_batches (
  batch_id    UUID PRIMARY KEY,
  artifact_id UUID NOT NULL,
  channel     TEXT NOT NULL CHECK (channel IN ('upload','kb_import')),  -- kb_import 预留
  file_name   TEXT NOT NULL DEFAULT '',
  sheet_name  TEXT NOT NULL DEFAULT '',
  row_count   INTEGER NOT NULL DEFAULT 0,
  created_by  TEXT NOT NULL,
  created_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

### 3.5 `kb_table_columns`（设计态列定义——表格维度）

```sql
CREATE TABLE kb_table_columns (
  artifact_id    UUID NOT NULL,
  column_id      TEXT NOT NULL,                 -- 形如 c0001
  column_name    TEXT NOT NULL,                 -- 逻辑列名
  column_type    TEXT NOT NULL CHECK (column_type IN ('text','int','float','date','enum','bool')),
  enum_values    JSONB,                         -- enum 时填；软约束（新值警告不阻断）
  is_primary_key BOOLEAN NOT NULL DEFAULT FALSE,
  is_indexed     BOOLEAN NOT NULL DEFAULT FALSE, -- 发布时据此生成表达式索引
  alias          JSONB NOT NULL DEFAULT '[]',   -- 改名历史（旧名读取层兼容）
  status         TEXT NOT NULL CHECK (status IN ('active','dropped')),  -- 删列=软删
  ordinal        INTEGER NOT NULL DEFAULT 0,    -- 列顺序
  PRIMARY KEY (artifact_id, column_id)
);
```

> 无 version 列：schema 变更走制品修订（发布时整体定格进 revisions.schema_json），列级 version 会组合爆炸。

### 3.6 `kb_table_rows`（行数据——表格维度；draft 与已发布版共表）

```sql
CREATE TABLE kb_table_rows (
  artifact_id UUID NOT NULL,
  revision    INTEGER NOT NULL,                 -- 0=draft（设计态工作区）；N=第 N 次发布快照
  row_key     TEXT NOT NULL,                    -- 业务主键值拼接；未声明主键时为生成 uuid
  data        JSONB NOT NULL,                   -- {"MOP":"NC20260601000295","L1分类":"数据业务",...}
  provenance  JSONB NOT NULL DEFAULT '[]',      -- [{batch_id,file_name,sheet_name,row_index},...] 多来源
  conflicts   JSONB NOT NULL DEFAULT '{}',      -- {"L2分类":"type_warning:..."} 校验/冲突标记
  ordinal     INTEGER NOT NULL DEFAULT 0,       -- 展示顺序（禁止当身份）
  updated_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_by  TEXT NOT NULL DEFAULT '',
  PRIMARY KEY (artifact_id, revision, row_key)
);
```

**jsonb 三字段分工**：`data`=唯一进前端网格/Agent 查询的业务值；`provenance`=行的来源账（侧栏/详情展示）；`conflicts`=质量标记（人工清理清单）。三者永不混装。

## 四、生命周期与版本控制

### 4.1 状态机

```
draft ──发布──▶ published(rev N) ──再编辑+发布──▶ published(rev N+1)
                   │
                   ├──停用(deprecate)──▶ deprecated ──再发布──▶ published
                   └──回滚(rollback)──▶ current_revision 拨回旧版（数据不动）

删除（owner only）：硬删+级联（members/columns/rows/revisions/batches 一并删；
                    对象挂载上线后此处增加引用计数检查位）
```

### 4.2 发布事务（三件事原子完成）

```sql
BEGIN;
-- ① 行复制定格
INSERT INTO kb_table_rows (artifact_id, revision, row_key, data, provenance, conflicts, ordinal, ...)
SELECT artifact_id, :N+1, row_key, data, provenance, conflicts, ordinal, ...
FROM kb_table_rows WHERE artifact_id=:id AND revision=0;
-- ② schema 快照 + 版本记录
INSERT INTO kb_artifact_revisions (artifact_id, revision, schema_json, row_count, ...)
VALUES (:id, :N+1, :当前active列定义数组, :draft行数, ...);
-- ③ 清空 draft + 拨指针 + 状态
DELETE FROM kb_table_rows WHERE artifact_id=:id AND revision=0;
UPDATE kb_artifacts SET current_revision=:N+1, status='published', updated_at=now() WHERE artifact_id=:id;
COMMIT;
-- 事务外：按 is_indexed 列生成/重建类型化表达式索引（见 §4.5）
```

前置校验：`usage_note` 非空（发布必填，SRA 实证说明卡缺"何时用/何时不用"制品等于没发布）。

### 4.3 编辑入口：ensure_draft 与 discard

```
ensure_draft()：所有设计态编辑动作（单格/批量/追加导入/schema 变更）统一入口
  rev0 无行 且 current_revision>0 → 先 checkout（INSERT SELECT current→rev0）
  然后执行编辑。设计态零历史、零撤销栈。

discard（丢弃 draft）：DELETE rev0 全部行 → 回到"与已发布版一致"的干净状态。
  乱改之后的逃生门，前端显式按钮+确认。
```

### 4.4 存档语义与存储账

- **发布点 = 存档点**。draft 期间改坏几格可看 diff 手改回来；改坏一片 discard 重来。
- 存储 = 平均行数 × 发布次数（快照式，未改行跨版本冗余、改过行是历史）。MVP 量级忽略；百万行×几十版时做 delta 存储（未变行引用旧版），纯内部优化不改查询语义。
- 行表按 artifact_id 列表分区的通道预留（MVP 不分区）。

### 4.5 索引：schema 驱动，发布时生成

发布后对 `is_indexed=TRUE` 的列生成类型化表达式索引（类型按 column_type cast，避免 TEXT 排序把 10 排在 9 前）：

```sql
CREATE INDEX idx_art_{id}_c001 ON kb_table_rows (artifact_id, revision, (data->>'MOP'));
CREATE INDEX idx_art_{id}_c007 ON kb_table_rows (artifact_id, revision, ((data->>'端口号')::int));
```

draft（rev0）不建索引（编辑频繁）。热点列后续可升级为**存储生成列**（`GENERATED ALWAYS AS (data->>'MOP') STORED`），由 56号账本使用信号触发——运营闭环与存储优化接通。

## 五、权限模型

### 5.1 归属与解绑（2026-10-16 拍板，修订 60号 拍板5）

- 制品**唯一归属一个 domain**（domain_id 列）；内容可组装自多个知识库+多个上传文件（provenance 天然多来源）。
- **与库权限完全独立，无嵌套无钳制**——支持策展开放：库里内容多，挑代表性内容做成制品开放给不该看整库的人，这是正常业务。
- 原"制品可见 ⊆ 所有来源库可读"的硬钳制作废。

### 5.2 角色矩阵

| 角色 | 元信息 | 设计态（rev0） | 运行态（已发布） | 发布/回滚/停用/discard | 成员管理 | 删除 |
|---|---|---|---|---|---|---|
| owner | ✓ | 编辑 | 读 | ✓ | ✓ | ✓ |
| editor | ✓ | 编辑 | 读 | ✓ | ✗ | ✗ |
| viewer | ✓ | **不可见** | 读 | ✗ | ✗ | ✗ |
| 非成员/跨域 | 404（反探测，与私有库同口径） | | | | | |

- 创建者自动 owner；域管理员对本域制品有管理权（对齐域 RBAC 体系）。
- viewer 不见设计态（上轮默认，改权限函数一行可放开）。

### 5.3 MCP 派生（无独立授权表）

密钥 → 所属用户 → 制品角色。get_knowledge 的 artifacts 视图只列"该用户 viewer+ 且 status=published"。**MCP 保持只读**（编辑/发布动作不走 MCP，与现有体系一致）。

### 5.4 知情提示（取代钳制的安全机制）

发布动作聚合 provenance 中的来源库，若含私有库 → 显式提示"本制品包含来自私有库 X 的 N 行内容，将随制品开放给制品成员"，创建者确认即过。**信任策展决策，让决策知情**。MVP 的 Excel 场景无库来源，不触发。

## 六、Excel 导入：三步向导（建表/追加两模式共用）

### 6.1 限制与基建

- 单 sheet ≤ 10 万行、≤ 200 列；多 sheet 用户选一个。
- 解析复用 55号 用户导入的 CSV-XLSX 基建（openpyxl 同栈，零新依赖）。

### 6.2 三步流程

```
第一步 选文件：上传 Excel（multipart），选 sheet。

第二步 列映射（两模式）：
  建表模式（首次）：展示推断的 schema 草案，用户调整——
    类型推断规则：抽样 cast（int/float/date 试探）→ distinct 少且非数字 → enum 候选
    （列出候选枚举值）→ 否则 text；首行默认表头（预览可改）
  追加模式（已有 schema）：左右两栏连线——
    ┌新文件列┐        ┌已有 schema 列┐
    │MOP编号   │──────▶│MOP (c001)    │ 模糊匹配自动建议（编辑距离/包含），人可改
    │L1 分类   │──────▶│L1分类 (c002) │
    │是否夜间执行│  ？  │（新列）       │ ◀ 文件有 schema 无 → 三选：
    └────────┘        └──────────┘     [加为新列][映射到"是否高危"][丢弃]
    schema 有文件无的列 → 该批行此列置 null（提示清单）
    语义映射（是否夜间执行→是否高危）靠人判断，AI 只给名字相似度建议，不自动拍板
    （错映射比漏映射危害大）

  两模式共用同一向导组件（建表=右边是新建列，追加=映射到已有列）。

第三步 预览确认：
  按映射后 schema 投影前 50 行 + 三个预检报告：
  ① 类型校验：失败格计数+样例 → 处理三选：该列改按 text / 容错导入（失败格置
     null+conflicts 标记）/ 阻断修改
  ② 主键冲突预检：命中 N 条将更新（UPSERT+provenance 追加）/ 新插 M 条
  ③ 与已发布版差异（见 §八，仅追加模式且有已发布版时）
  确认 → 建 batch 记录 → 灌入 rev0（ensure_draft 先行）→ provenance 记
  [{batch_id, file_name, sheet_name, row_index}]
```

### 6.3 主键规则

- 制品声明主键列（可多列组合）→ `row_key` = 主键值拼接；未声明 → 生成 uuid。
- **知识库导入通道（二期）将强制先声明主键**（增量合并无主键无意义）；Excel 上传不强制（一次性数据），但 UI 引导选主键。
- 改主键（有数据时）= 重算全部 row_key + 冲突检查，走独立确认流程。

## 七、表格编辑功能

### 7.1 schema 管理（演进规则）

| 操作 | 行为 | 动存量数据 |
|---|---|---|
| 加列 | columns 加一行 | 不动（旧行该列读出 NULL） |
| 改列名 | 写入 alias | 不动（读取层旧名→新名兼容） |
| 改类型 | 重校验存量（cast 报告） | 不动（校验失败落 conflicts） |
| 删列 | status=dropped 软删 | 不动（单调扩展铁律） |
| 设主键 | 见 §6.3 | 重算 row_key |
| 标索引 | is_indexed 翻转 | 下次发布生效 |

### 7.2 数据编辑

| 功能 | 实现 |
|---|---|
| 单格更新 | `jsonb_set(data, '{列名}', '"新值"')`，走 ensure_draft |
| 批量赋值 | `UPDATE SET data = data \|\| '{"列名":"值"}' WHERE ...`（一条 SQL 批量） |
| 行增删 | 增（给 row_key 或按主键）/删（DELETE rev0 行） |
| 追加导入 | §6 追加模式（主键 UPSERT + provenance 追加） |
| 并发控制 | 制品级乐观锁（updated_at/ETag 校验，冲突 409 重试）；不做单元格级锁 |

## 八、发布预览与版本 diff

发布确认页固定带差异区（draft rev0 vs current_revision，SQL 现算两 revision 行集差，不额外存储）：

```
本次发布将产生的变化：
  新增 12 行（展开：MOP=NC20260723... 等）
  修改  3 行（列级明细：NC20260601... 的 L2分类 '网络部署/扩容'→'扩容/网络部署'）
  删除  1 行（NC20260603000441 已被过滤）
  [usage_note 必填框] [确认发布]
```

多轮迭代的刹车片：**看清楚改了什么再发布**。

## 九、查询：端到端

### 9.1 前端看一张表（六步）

```
① 前端：GET /artifacts/{id}/table/rows?page=1&size=50（设计态页带 ?draft=1）
② 后端定 revision：draft=1 → 0；否则 → kb_artifacts.current_revision
③ 取列定义：设计态 → kb_table_columns WHERE status='active' ORDER BY ordinal（实时反映编辑）
           运行态 → kb_artifact_revisions.schema_json（发布定格快照）
④ 取行：SELECT row_key, data, provenance, conflicts, ordinal
        FROM kb_table_rows WHERE artifact_id=? AND revision=? ORDER BY ordinal LIMIT 50
        （keyset 翻页）
⑤ 后端拼装"一张表"：
   {columns:[{id,name,type,enum_values,is_primary_key}...],
    rows:[{row_key, cells:{...}, provenance:[...], conflicts:{}}...]}
⑥ 前端渲染：columns 画表头（enum 列标签/编辑时下拉），cells 按列名填格，
   row_key 当行 id，provenance/conflicts 点行侧栏展示（不进网格）
```

### 9.2 Agent 消费（MCP）

| 通道 | 内容 |
|---|---|
| **发现** | get_knowledge 加 artifacts 视图：说明卡列表（title+description+usage_note），只含"该用户 viewer+ 且 published" |
| **查询** | st_ 协议目标源扩展制品类：select/where/order_by/limit/cursor 全复用，revision 固定=current_revision |
| **溯源** | 行 provenance 随查询返回（Excel 场景即 file/sheet/row_index） |

设计态（rev0）对 Agent **永远不可见**。

## 十、API 清单（REST，web 用）

```
制品维度：
POST   /api/v1/artifacts                          创建（domain_id, title, description）
GET    /api/v1/artifacts                          列表（我参与的）
GET    /api/v1/artifacts/{id}                     详情（元信息+schema+采样行）
PATCH  /api/v1/artifacts/{id}                     改元信息
DELETE /api/v1/artifacts/{id}                     删除（owner，硬删级联）
POST   /api/v1/artifacts/{id}/publish             发布 {change_summary}（diff 预览→usage_note 必填）
POST   /api/v1/artifacts/{id}/rollback/{revision} 回滚（拨指针）
POST   /api/v1/artifacts/{id}/deprecate           停用
POST   /api/v1/artifacts/{id}/discard             丢弃 draft
GET    /api/v1/artifacts/{id}/diff                draft vs current 差异
成员：
GET/POST/PATCH/DELETE /api/v1/artifacts/{id}/members
表格维度：
POST   /api/v1/artifacts/{id}/table/upload        上传 Excel → 预览 token
GET    /api/v1/artifacts/{id}/table/preview/{token} 预览（schema 草案/列映射+前 50 行）

GET    /api/v1/artifacts/{id}/table/columns       列定义
POST   /api/v1/artifacts/{id}/table/columns       加列
PATCH  /api/v1/artifacts/{id}/table/columns/{cid} 改列（名/类型/枚举/主键/索引/软删）
GET    /api/v1/artifacts/{id}/table/rows          查行（?draft=1&page&size&sort&filter）
PATCH  /api/v1/artifacts/{id}/table/rows/{row_key} 单格/行更新
POST   /api/v1/artifacts/{id}/table/rows/batch-assign  批量赋值
```

## 十四、决策记录（2026-10-15/16 讨论拍板汇总）

| # | 决策 | 要点 |
|---|---|---|
| 1 | 行存储 jsonb（否 EAV） | 宽读 O(1)、类型保留、批量写快 20 倍、演进零成本；schema 表升级为"索引生成器"；热点列可升级存储生成列 |
| 2 | 行地址=业务主键 | row_key=主键值拼接；ordinal 仅展示；知识库导入通道将强制主键 |
| 3 | 制品挂 domain，与库权限解绑 | 策展开放合法（库不开放、制品开放）；硬钳制作废，改发布时知情提示；source_kbs 列删除 |
| 4 | 版本=发布点快照 | 设计态零历史（rev0 工作区）；发布=复制+快照+清 draft+拨指针；回滚=拨指针；discard=删 rev0；无细粒度撤销栈 |
| 5 | 追加导入带列映射 | 三步向导两模式共用；文件新列三选（加列/映射/丢弃）；缺列置 null 提示；语义映射人拍板 |
| 6 | 发布前 diff 预览 | 新增/修改/删除行级差异+列级明细，看清楚再发布 |
| 7 | MCP 权限派生 | 密钥→用户→制品角色；MCP 只读；无独立授权表 |
| 8 | viewer 不见设计态 | 只读运行态+元信息；需要时权限函数一行放开 |
| 9 | usage_note 发布必填 | 说明卡=发现机制核心，"何时用/何时不用"不可缺 |
| 10 | 枚举软约束 | 新值警告不阻断导入，人工可扩充枚举值 |
| 11 | 删除=硬删级联+预留引用检查位 | 对象挂载上线后补 mounts/refs 引用计数检查 |
| 12 | 类型推断与冲突策略 | 抽样 cast→enum 候选→text；类型失败三选（改 text/容错+conflicts/阻断）；主键冲突三选（默认阻断重选主键） |
